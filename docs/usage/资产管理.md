# 资产管理

资产管理沿用平台账户、权限和业务数据库。网页与客户端读取同一份库存；离线不能登记库存操作。

## 型号、校区和实物

管理员、项管及获授 `assets.manage` 的成员可维护校区、类别和型号。不同实际型号分别建档；同一型号可关联多个嘉立创 C 编号。商品编号表示型号，不表示某一台实物。

- **耗材**按整数数量管理。普通成员仍可入库、调整数量和领用，必须填写用途／备注。累计领用与剩余库存分开显示。
- **新非耗材**逐件建档。管理人员登记实收件数，可逐行填写厂家 SN。每件设备获得永久身份；没有厂家 SN 也不会共用身份。
- 非耗材总量由在册实物计算，包含借出、装车、待检查和维修，排除已确认报废、遗失及销毁。不能直接修改总数；旧客户端调用数量接口也会被拒绝。
- 切换校区立即更新列表。点击单件型号打开抽屉，可跨页选择实物，再统一填写原因提交；原详情地址继续提供分校区汇总和全部流水。

内部标签暂使用机器标识 `U:<单件ID>` 和 `M:<物料ID>`。这不是最终业务编号前缀；补打标签沿用原身份。不得修改数据库主键来重新编号。

管理人员编辑耗材或旧数量台账时，可在同一窗口选择校区并填写调整后的在库数量，也可新建校区。资料、库存与原因记录一起保存，库存版本过期时全部拒绝；不选择校区则只保存资料，不改变其他校区及借单。单件型号提供“调整单件数量与校区”入口，通过具体设备的建档、移动、处置维护数量。管理员可填写原因更正计量单位名称，不做数量换算；已有业务历史的物品仍不能直接切换耗材／非耗材类型，以免历史借单与实物身份失配。

## 包装扫码与入库

点击「新增物品」后可选择「手动填写」或「扫码登记」。普通成员仅显示扫码登记，可登记已有耗材，不能新建目录。首页不再单独显示扫码按钮。

「扫码工作台」接受内部标签、C 编号和嘉立创采购包装文本，例如合成样本：

```text
{on:TEST-ORDER,pc:C12345,pm:TEST-PART,qty:100,mc:,cc:1,pdi:UNKNOWN,hp:1}
```

解析只读取键值，不执行代码，也不把它当作标准 JSON。`pc` 为商品编号、`pm` 为型号、`qty` 为标签数量、`on` 为订单标识；空值及未知字段保留，不猜测 `pdi` 的含义。

1. 扫描、上传相册图片或手动输入原文。扫描本身不改变库存。
2. 已关联商品进入预览；未知商品由管理人员确认建档或关联。普通成员不能绕过目录权限。未知包装商品的“确认建档”同时展示实收数量、校区和必填备注，确认后一次完成目录、供应商映射和入库；任一步失败均不保存。
   耗材和非耗材的实收数量都默认采用扫描得到的有效 `qty`，可按实际收货修改；缺失或非法数量留空，不能自动当作 1。没有校区时，管理人员可以在该窗口新建校区。之前只建目录、没有入库来源的零库存不会凭空回填，需重新扫码登记或核对后调整。
3. 核对标签数量，填写**实收数量、实际校区、必填用途／备注**。开封包装按实收数入库；标签数量缺失或非法时必须补录，不默认一件。
4. 确认后耗材增加数量；非耗材由管理人员按实收件数建立单件记录。单次非耗材建档最多 100 件。
5. 选择“收集包装”可预览整批入库，每批最多 20 个包装，受接口总请求大小限制；任一条失败则整批回滚，清单保留。

同一清单重复扫描完整标签不会累计数量。历史中已有相同完整标签时，必须重新核对并填写追加收货／另一包的原因；提交前又出现新登记则返回冲突，要求重新预览。同一订单同一商品可以有多个包装，不用 `on + pc` 判重。实际包装是否相同仍需人工核对，标签不是不可伪造的包装序列号。

包装原文、解析结果、标称数量、实收数量、操作者和原因与库存同事务保存，在型号流水的“包装入库来源”中查看。真实标签和采购信息只进入业务数据库，不进入源码。

国内商品自动查询尚未接入。取得官方接口资格和文档后另批实现；包装解析、手工建档和借还不依赖外部接口。

## 借还、责任与位置

普通成员可登记本人借还及设备移动。管理人员可代办，操作记录同时保留实际操作者、保管人和原因。批量操作包含每件设备的版本；任一件被他人更新时整批拒绝，须重新核对。

- 借用只接受正常、在库、未安装的单件；归还对应具体设备，可选择其中一部分归还。
- “我的借用”页面统一展示未还借单、本人单件与待接收，不再另开单件窗口。其中单件区域展示本人保管的设备和等待本人接收的移交。责任移交在接收人确认前不生效；期间发生其他操作会使原移交失效。
- 顶部汇总分别显示按数量借用的单数、未还单件数和待接收件数，始终统计全部校区；切换单件校区或翻页不改变汇总范围。“暂无按数量登记的未还借单”仅针对数量借单分组。
- 本人设备可登记实际移动和异地归还，校区跟随实物；责任人不会因校区改变而改变。
- 管理人员维护机器人、测试平台等使用对象，可关联现有造车组。安装必须指定已借用的正常设备，安装位置自由填写；安装不结清个人借用。
- 已安装设备归还、送修或处置须明确确认拆卸，可在一次提交中完成。已装车设备移动由管理人员核对整车清单，不能只改变其中几件的位置。
- 损坏归还结清借用并进入待检查，管理人员确认恢复后才可再次借用。送修保留原保管责任，直到归还或确认移交。
- 报废、遗失单独填写原因结案，保留历史；找回或误报恢复原身份，进入待检查，不重开旧借单。已实际销毁不可恢复。
- 保管纠错追加前后状态及原因，不覆盖旧流水，也不回滚后续历史。

## 盘点与旧数量台账迁移

管理人员可从当前列表页选择小范围型号及一个校区，启动仓库在库或全量在册盘点；最多 20 个型号、1000 件。该校区型号在盘点期间冻结流转，入库和移入也被阻止。扫码清单登记已看到的实物，范围外扫码作为观察差异记录。结束时核对漏扫清单并填写原因，**未扫描只表示待核实，不自动记遗失**。已结束盘点可通过历史编号查询。

旧非耗材保留原数量台账，不自动分配身份。逐型号执行：

1. 打开原详情中的“实物核对迁移”，冻结型号。
2. 核对每个校区的仓库实物及每笔未还借单，明确登记对应实物，可填写厂家 SN。
3. 各校区在库数和每笔借单未还数均完全对应后，管理人员确认切换。误录可取消本次核对、解冻后重新登记。
4. 切换后由单件计算库存；旧数量和旧借单保留为历史快照，不再计入当前库存，也不允许旧接口重复归还。

耗材及尚未迁移的旧台账保留原数量操作和追加纠错规则；有后续操作导致反向数量不成立时拒绝纠错。所有正式写操作仍使用平台登录、CSRF、事务及请求幂等机制。

网络结果不明时保留原表单与请求标识，使用“重试上次提交”核实同一请求，不另建一笔。身份、服务器改变后不得沿用另一账户的请求。刷新后可从会话恢复待确认请求；关闭整个会话后需先核对服务端流水。

服务器错误、页面代替接口响应或损坏 JSON 也属于结果不明。此时不要新建另一笔登记，继续重试原请求。跨校区移动、异地归还和整车移动的记录可在原校区和目标校区查询，历史流水保持原样。

## 扫码与打印

电脑扫码枪按键盘输入使用，可选 Enter、Tab 或手动查询；只在工作台主动进入时聚焦编号框，不抢占备注输入。手机可从相册识别；安全上下文提供相机入口。拒绝授权或 HTTP 网页不能打开相机时，使用相册／手动输入。图片在设备内解码，不发送给供应商。

相机识别后若解析失败，原标签与已选清单保留，点击“重试此标签”即可重试，无需关闭相机。重复画面不会自动重复请求或累计数量；只有成功解析才提示识别成功。停止相机或关闭窗口后，迟到结果不会更新页面。

解码器及条码生成组件使用本地固定版本，不依赖运行时 CDN。Android 只给配置的可信 HTTPS 页面或本地安全页面授予视频采集，导航离开、切换服务器或页面隐藏时结束相关相机使用；外链视图无通用原生命令。

打印预览直接显示服务器生成的 PDF，可按页查看真实排布；下载的是当前预览同一份文件。修改纸张或尺寸会重新生成，失败时清除旧预览并显示错误。旧客户端若提示升级才能保存，可先使用浏览器下载；标签身份不会因重新预览或补打而改变。

物料卡片和详情可打印型号标签；单件抽屉勾选实物打印单件标签。预览包含文字、Code 128 和二维码，可下载 A4 或自定义热敏尺寸 PDF。标签宽 40–190 mm、高 25–270 mm；打印选择实际尺寸，先试打一张核对可读性。扫描物料标签只能查询型号，不能替代具体设备进行借还。

## 客户端与数据回滚

新本地页面根据 bootstrap 的 `asset_units_enabled` 显示新增入口，旧服务器不声明时保留旧资产功能。客户端使用同一后端规则和现有认证下载通道。

迁移前备份实际业务数据库。增量迁移重复执行不会清空表；代码回滚不得删除身份、来源或流水。产生单件数据后，不能直接运行不认识单件模型的旧代码继续数量操作，应停写核对并采用兼容修复。若需要恢复快照，先核对快照后的业务差异，再单独确认。

源码与软件测试不代表已上线或真机通过。正式部署、安装包、手机相机、实体扫码枪和打印机分别验收。

资产弹窗采用圆角边框及内部滚动；点击四周遮罩、取消或 Escape 可退出，保存提交期间暂不关闭。关闭扫码窗口同时释放摄像头。
