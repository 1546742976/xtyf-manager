# 资产管理

## 新版物料仓库的日常用法

首页先按名称或规格搜索（输入后自动搜索），再按校区、类别和物料的实际使用方式筛选。页面支持“全部”“设备／工具”“元件／数量耗材”“螺丝等自由取用”“需要补货”五种视图，筛选与总数均由后端处理，切换视图不丢失搜索条件。“需要补货”包含已标记不足的状态耗材，以及当前筛选范围内数量为 0 的数量耗材，不把仅仅借出的设备判为缺货。

列表默认采用紧凑行布局，直接显示型号、规格、可用数量及主要操作。普通成员无需进入管理设置即可借还单件、领用元件，螺丝等自由取用耗材仍按校区直接标记充足／不足，平时不扫码、不登记逐次取用。管理人员的校区、类别、使用对象与盘点功能集中在独立的次级工具行。移动端改为单列并允许横向滑动类型筛选。

库存列表、类别整理、数量借单、实物列表与流转记录共用分页控件，提供首页、上一页、邻近页码、下一页、末页和输入页码跳转；每页可选 20、50、100 条，新页面默认 20 条。搜索、改变筛选或每页条数后回到第一页；页码超出结果范围时显示有效末页。手机端仍可输入页码和改变每页条数。

资产管理沿用平台账户、权限和业务数据库。网页与客户端读取同一份库存；离线不能登记库存操作。

## 型号、校区和实物

管理员、项管及获授 `assets.manage` 的成员可维护校区、类别和型号。不同实际型号分别建档；同一型号可关联多个嘉立创 C 编号。商品编号表示型号，不表示某一台实物。名称、规格相同通常提示核对已有档案；确认是独立物品时，可勾选另建并填写原因，生成独立 `M:<物料ID>`，不会覆盖已有档案或历史。

- **普通耗材（螺丝、螺母等）**可选择“充足／不足”，自由取用，无需扫码或逐次登记。卡片按校区显示两种状态，任何登录成员都能一键标记不足，核对或补齐后标记充足。状态变更保留操作者和流水。
- **嘉立创元件等数量耗材**继续按整数数量管理。普通成员仍可扫码入库、调整数量和领用，必须填写用途／备注。累计领用与剩余库存分开显示。
- **新非耗材**逐件建档。管理人员登记实收件数，可逐行填写厂家 SN。每件设备获得永久身份；没有厂家 SN 也不会共用身份。
- 非耗材总量由在册实物计算，包含借出、装车、待检查和维修，排除已确认报废、遗失及销毁。不能直接修改总数；旧客户端调用数量接口也会被拒绝。
- 切换校区立即更新列表。点击单件型号打开抽屉，可跨页选择实物，再统一填写原因提交；原详情地址继续提供分校区汇总和全部流水。

内部标签暂使用机器标识 `U:<单件ID>` 和 `M:<物料ID>`。这不是最终业务编号前缀；补打标签沿用原身份。不得修改数据库主键来重新编号。

管理人员编辑耗材或旧数量台账时，可在同一窗口选择校区并填写调整后的在库数量，也可新建校区。资料、库存与原因记录一起保存，库存版本过期时全部拒绝；不选择校区则只保存资料，不改变其他校区及借单。单件型号提供“调整单件数量与校区”入口，通过具体设备的建档、移动、处置维护数量。管理员可填写原因更正计量单位名称，不做数量换算；已有业务历史的物品仍不能直接切换耗材／非耗材类型，以免历史借单与实物身份失配。

## 普通耗材的充足／不足

手动新建物品后选择“耗材”，默认采用“充足／不足”；嘉立创元件请选择“数量管理”，填写 C 编号时也会保持数量管理。采购包装自动准备的待建档资料默认采用数量耗材、单位“个”、未分类。

已有螺丝等物料可由管理人员在“编辑物品 → 耗材管理方式”中切换，填写一次调整原因。不会按名称批量猜测用途，也不会自动改变现有元件。已关联嘉立创 C 编号的物料保留数量管理。

状态按校区独立保存，初始为“不足”，请核对实物或补齐后标记“充足”。平时取用无需任何操作，余量不足时直接点卡片上的“标记不足”；补齐后点“补齐了，标记充足”。不再显示数量、领用或数量调整按钮。

切换为状态管理时保留原数量及历史，旧数量接口不能继续写入。若以后切回数量管理，各校区当前库存从 0 开始，原余额保存在调整记录中，需重新编辑库存盘点；不会把自由取用前的旧数量当作当前余量。状态更新也支持版本冲突检查与网络结果不明时重试原请求。

## 包装扫码与入库

首页“扫一扫”可先识别再选操作；“新增 / 扫码入库”中的扫码入口直接进入采购入库。普通成员可以登记允许入库的已有物料，建档和编号关联仍需管理权限。

「扫码工作台」接受内部标签、C 编号、嘉立创采购包装文本，以及厂家二维码、条形码的原文。例如合成包装样本：

```text
{on:TEST-ORDER,pc:C12345,pm:TEST-PART,qty:100,mc:,cc:1,pdi:UNKNOWN,hp:1}
```

解析只读取键值，不执行代码，也不把它当作标准 JSON。`pc` 为商品编号、`pm` 为型号、`qty` 为标签数量、`on` 为订单标识；空值及未知字段保留，不猜测 `pdi` 的含义。

1. 在“采购入库”模式连续扫描。每次读到标签就自动加入清单，资料查询排队完成，不需要逐包点击添加。扫码枪输入会立即清空，供下一次扫描使用。
2. 已明确关联物料的包装直接准备入库；尚未关联的商品自动准备待建档资料，无需逐条点建档。默认是**数量耗材、单位“个”、未分类**；名称优先采用商品资料，查询失败时采用标签型号，再缺失则使用商品编号；规格采用商品型号或标签型号。同一供应商商品编号的不同包装共用待建档资料，同名或同规格只作为关联建议，不自动合并档案。可随时“编辑资料”、选择已有型号或另建独立档案。
3. 厂家原码和无法按已知标签格式解析的内容也保留在清单中，管理人员可通过“编辑资料”补充型号或选择已有型号。保存草稿只暂存于清单，扫码、编辑资料或取消核对都不会提前保存新档案、编号关联或库存。
4. 点击取景器下方“清单”，再点击“扫完了，核对整批”。逐条核对**实收数量、实际校区、必填用途／备注**。包装数量默认采用有效 `qty`，缺失或非法值留空，允许进入核对页补填，填妥前不能提交；校区可以统一设置，也可逐条修改。返回继续扫码时，已填写的数量、校区和备注会保留。
5. 最后一次确认时统一完成建档、编号关联、库存和来源记录；同一批共用的草稿只创建一份档案。每批最多 **20 条扫码记录**，请求总大小不超过 **16 KiB**，达到限制时需拆批；逐件物料按实收件数建立身份，包装每条最多 100 件，序列号码每条只登记一件。数量非法、校区停用、权限不足、匹配或历史版本变化，以及其他任一条保存失败都会整批回滚，清单保留供核对；成功后移除已提交条目。

扫描清单和待建档资料暂存在当前页面，关闭扫码窗口再打开仍保留，刷新或离开页面会丢失尚未提交的清单。普通成员可给已有明确关联的数量物料入库；自动建档、选择型号后新增编号关联、另建重码档案及逐件入库均需管理权限。

### 电机等设备使用厂家原码

对于每台都有厂家序列号码的电机，在采购入库中直接扫描原码，选择“编辑资料”，填写型号并选择“设备／工具”；默认逐件管理。无需根据任意码内容猜测名称、型号或用途。首次填写型号资料后，后续原码可以选择该已有型号，也可勾选多个条目统一填写型号或归入同一已有型号。

同型号共用物料档案，每个序列号码对应一台独立实物，自动取得 `U:<单件ID>`。厂家原码绑定到具体实物，内部编号无需实际打印或贴在电机上；以后扫描原码即可办理该台设备的借用、归还、移动和盘点。如果选择按数量管理，原码关联型号，实收数量需要自行填写，不能用来区分具体哪台设备。

### 重码、重复扫描与历史收货

已匹配物料或实物时，管理人员仍可选择“这是另一物品，另建档案”；同型号的另一台设备可选择“在此型号下新增实物”。需要在同批登记另一件具有相同原码的物品时，使用“新增重码条目”并填写冲突或另建说明。新对象取得独立内部编号，保留原码与说明，不覆盖已有绑定、库存或历史。

原码对应多个物料或实物时，每次扫描都需要选择候选；候选展示名称、规格、`M:`／`U:` 编号，实物还显示校区和状态。不会自动沿用上次选择。厂家码恰好与内部 `M:`、`U:` 或供应商编号内容相同时，也会合并显示精确匹配候选供核对。通用原码仅去除首尾空白后精确匹配，保留大小写，不自动访问码内网址；原文最多 4096 字符。

手机打开摄像头后，取景器直接叠加清单数量、查询中／待处理数量和最近一条结果。读到标签有短提示音和框线反馈，可关闭提示音；重复标签会提示但不会重复计数。手机扫描时主要按钮保留在一行，点击“清单”停止相机并查看列表，再点击“继续扫码”恢复。提示音受浏览器音频策略和系统音量影响，文字反馈始终保留。

同一清单普通重复扫描不会累计数量，已入库的设备再次扫描也不会直接新增实物；另一件重码设备必须明确新增。历史中已有相同完整标签时，必须重新核对并填写追加收货／另一包的原因；提交前又出现新登记则返回冲突，要求重新预览。同一订单同一商品可以有多个包装，不用 `on + pc` 判重。实际包装是否相同仍需人工核对，标签不是不可伪造的包装序列号。

包装原文、解析结果、标称数量、实收数量、操作者和原因与库存同事务保存，在型号流水的“包装入库来源”中查看。真实标签和采购信息只进入业务数据库，不进入源码。

商品资料通过 LCSC 官方公开商品页查询，并标注来源；查询失败时仍保留标签解析和本地匹配，不自动使用商城库存作为本地库存。

## 批量整理库存类别

管理人员可在“类别管理”中新增、改名或停用类别，也可点击“整理库存类别”进入库存列表的整理模式。直接复用原列表的名称／规格搜索、校区、物料类型及类别筛选，类别中增加“未分类”。

勾选需要整理的物料，可使用“选择本页”、逐条取消或清空选择，一次最多 **100 种物料**。翻页、搜索或切换筛选后保留已勾选项，界面显示总选择数和当前不可见的选择数；仅修改明确选中的物料。选择目标类别后，确认窗口展示目标类别和物料总数，也可选择“未分类”清除类别。

类别按物料型号维护，型号下全部实物沿用其类别，不改库存数量。提交时检查每种物料和目标类别的版本；任一物料被其他人修改或目标类别更新、停用时整批拒绝，保留选择供刷新核对。成功修改会更新物料版本并追加类别维护流水。

## 借还、责任与位置

普通成员可登记本人借还及设备移动。管理人员可代办，操作记录同时保留实际操作者、保管人和原因。批量操作包含每件设备的版本；任一件被他人更新时整批拒绝，须重新核对。

- 借用只接受正常、在库、未安装的单件；归还对应具体设备，可选择其中一部分归还。
- “我的借用”页面统一展示未还借单、本人单件与待接收，不再另开单件窗口。其中单件区域展示本人保管的设备和等待本人接收的移交。责任移交在接收人确认前不生效；期间发生其他操作会使原移交失效。
- 顶部汇总分别显示按数量借用的单数、未还单件数和待接收件数，始终统计全部校区；切换单件校区或翻页不改变汇总范围。“暂无按数量登记的未还借单”仅针对数量借单分组。
- 本人设备可登记实际移动和异地归还，校区跟随实物；责任人不会因校区改变而改变。
- 管理人员维护机器人、测试平台等使用对象，可关联现有造车组。安装必须指定已借用的正常设备，安装位置自由填写；安装不结清个人借用。
- 已安装设备归还、送修或处置须明确确认拆卸，可在一次提交中完成。已装车设备移动由管理人员核对整车清单，不能只改变其中几件的位置。
- 损坏归还结清借用并进入待检查，管理人员确认恢复后才可再次借用。送修保留原保管责任，直到归还或确认移交。
- 报废、遗失单独填写原因结案，保留历史；找回或误报恢复原身份，进入待检查，不重开旧借单。已实际销毁不可恢复。
- 保管纠错追加前后状态及原因，不覆盖旧流水，也不回滚后续历史。

## 盘点与旧数量台账迁移

管理人员可从当前列表页选择小范围型号及一个校区，启动仓库在库或全量在册盘点；最多 20 个型号、1000 件。该校区型号在盘点期间冻结流转，入库和移入也被阻止。扫码清单登记已看到的实物，范围外扫码作为观察差异记录。结束时核对漏扫清单并填写原因，**未扫描只表示待核实，不自动记遗失**。已结束盘点可通过历史编号查询。

旧非耗材保留原数量台账，不自动分配身份。逐型号执行：

1. 打开原详情中的“实物核对迁移”，冻结型号。
2. 核对每个校区的仓库实物及每笔未还借单，明确登记对应实物，可填写厂家 SN。
3. 各校区在库数和每笔借单未还数均完全对应后，管理人员确认切换。误录可取消本次核对、解冻后重新登记。
4. 切换后由单件计算库存；旧数量和旧借单保留为历史快照，不再计入当前库存，也不允许旧接口重复归还。

迁移旧借单时保留原借单中的成员 ID 与借用时姓名；即使该成员现已停用或逻辑删除，也可在完成实物与未还数量核对后迁移，不需要恢复其账户。**这不代表允许向停用或已删除成员新增借用或移交。**迁移后的历史保管设备可由资产管理人员登记归还或纠错。

数量耗材及尚未迁移的旧台账保留原数量操作和追加纠错规则；有后续操作导致反向数量不成立时拒绝纠错。所有正式写操作仍使用平台登录、CSRF、事务及请求幂等机制。

网络结果不明时保留原表单与请求标识，使用“重试上次提交”核实同一请求，不另建一笔。身份、服务器改变后不得沿用另一账户的请求。刷新后可从会话恢复待确认请求；关闭整个会话后需先核对服务端流水。

服务器错误、页面代替接口响应或损坏 JSON 也属于结果不明。此时不要新建另一笔登记，继续重试原请求。跨校区移动、异地归还和整车移动的记录可在原校区和目标校区查询，历史流水保持原样。

## 扫码与打印

电脑扫码枪按键盘输入使用，可选 Enter、Tab 或手动查询；只在工作台主动进入时聚焦编号框，不抢占备注输入。手机可从相册识别；安全上下文提供相机入口。拒绝授权或 HTTP 网页不能打开相机时，使用相册／手动输入。图片在设备内解码，不发送给供应商。

相机识别后若解析失败，原标签与已选清单保留，点击“重试此标签”即可重试，无需关闭相机。重复画面不会自动重复请求或累计数量；只有成功解析才提示识别成功。停止相机或关闭窗口后，迟到结果不会更新页面。

解码器及条码生成组件使用本地固定版本，不依赖运行时 CDN。Android 只给配置的可信 HTTPS 页面或本地安全页面授予视频采集，导航离开、切换服务器或页面隐藏时结束相关相机使用；外链视图无通用原生命令。

打印预览直接显示服务器生成的 PDF，可按页查看真实排布；下载的是当前预览同一份文件。修改纸张或尺寸会重新生成，失败时清除旧预览并显示错误。旧客户端若提示升级才能保存，可先使用浏览器下载；标签身份不会因重新预览或补打而改变。

物料卡片和详情可打印型号标签；物料列表进入“批量操作”后，可跨页多选最多 100 种型号并一次生成多张标签。退出多选再进入仍保留选择；批量面板也提供原有的类别整理，类别修改仍需管理权限。单件抽屉可勾选多台实物打印单件标签。文字描述、二维码、Code 128 条形码可分别开关，至少保留一项；关闭的部分不再占用打印空间，纯二维码或纯条形码标签不附带任何文字。可下载 A4 或自定义热敏尺寸 PDF；每次只渲染当前 PDF 页，可翻页查看全部标签，不截断为前 12 张。标签宽 6–190 mm、高 6–270 mm，默认 50×30 mm；支持自动/手动左右或紧凑布局。名称、具体型号／规格、厂家 SN、物料／单件编号分别设置 4–36 pt 字号及换行或单行省略；“统一字号”可快速设置各项，“按当前尺寸推荐字号”提供初始建议。默认按所设字号为上限自动缩小以适应文字区域，取消自动缩小即可固定字号；换行超出区域也会省略，不会覆盖码区。字宽支持 70%–110%，本浏览器会记住内容开关和全部排版设置。小标签会提示可读性风险；打印选择实际尺寸，先试打一张核对可读性。

单件标签的二维码和条形码使用同一个 `M:物料编号/U:单件编号`，例如 `M:12/U:42`。每个单件始终带固定的内部编号，有无厂家 SN、厂家 SN 是否重复均不影响区分；补打沿用原编号，不修改厂家 SN 或库存数据。旧 `U:42` 单件标签和 `M:12` 物料标签仍能识别，新单件码还会校验物料归属。扫描物料标签只能查询型号，不能替代具体设备进行借还。

### 手机通过局域网调试摄像头

`http://电脑IP:8520` 不是手机浏览器认可的安全上下文，不能调用实时摄像头；电脑上的 `localhost` 例外不适用于手机访问电脑。需要让手机通过受信任的 HTTPS 访问。证书告警页面上的“继续访问”不能替代证书信任设置。

1. Windows 使用 **`start.bat`** 一起启动 HTTP 与 HTTPS 服务，启动器会自动选择有网关的物理网卡地址。原来单独启动的 `python app.py` 应先在其终端停止，以免占用 HTTP 端口。如果有多张物理网卡，可在项目目录指定地址（替换为当前 Wi-Fi 的 IPv4）：

   ```powershell
   .\start.bat --ip 192.168.1.100
   ```

   启动器在同一进程内运行原有业务程序与 HTTPS 入口，手机地址为 `https://192.168.1.100:8521/assets`。`PROGRESS_DB` 等原有环境变量继续生效；HTTP 端口沿用 `PORT`（默认 `8520`），HTTPS 端口可用 `--port` 修改。它不自动安装系统信任、不修改防火墙、不创建后台常驻服务。

   如果要保留另一个终端正在运行的 HTTP 服务，只启动代理：`python deploy/local_https.py --ip 192.168.1.100`。此模式不会导入业务程序或读取数据库；原服务端口不为 `8520` 时，加 `--upstream-port 原端口`。

2. 将工具生成的 **公开证书** `.build-tools/local-https/root-ca.cer` 通过文件传输复制到手机，核对工具打印的证书 SHA-256 指纹后安装。

   - Android：在系统设置中搜索“安装证书”或“CA 证书”，选择安装 CA 证书并选取该文件。不同厂商的菜单位置不同；安装后重新打开浏览器。
   - iPhone：安装证书描述文件后，还要到“设置 → 通用 → 关于本机 → 证书信任设置”中，为本地调试根证书开启完全信任。仅安装描述文件不会自动信任 TLS，见 [Apple 官方说明](https://support.apple.com/zh-cn/102390)。

   只传输 `root-ca.cer`，私钥留在电脑。生成目录已被 Git 忽略。工具复用现有根证书；电脑 IP 变化时，使用新 IP 重新运行即可更新服务证书。

3. 手机与电脑连接同一局域网，在浏览器打开命令输出的 `https://电脑IP:8521/assets`，进入“扫一扫 → 摄像头 → 打开摄像头”，允许网站使用相机。有多个镜头时可在“切换摄像头”中选择。

如果 HTTPS 页面无法连接，确认终端仍在运行、IP 和端口正确，以及本机防火墙允许该端口的局域网访问；若仍出现证书警告，先检查手机是否已安装并信任本次生成的证书。结束调试时按 `Ctrl+C`：通过 `start.bat` 启动时会同时停止 HTTP 和 HTTPS；独立代理模式只停止 HTTPS，原 HTTP 服务不受影响。不再需要时，可在手机设置中移除这张本地调试证书。

仅准备证书、不启动监听时，追加 `--prepare-only`。本地 HTTPS 的原理参见 [Chrome 团队的本地 HTTPS 说明](https://web.dev/articles/how-to-use-local-https)；此工具是开发代理，不用于生产部署。

## 客户端与数据回滚

新本地页面根据 bootstrap 的 `asset_units_enabled` 显示单件功能，根据 `asset_intake_enabled` 和物料目录的 `intake_enabled` 显示新版入库、类别整理及分页入口；旧服务器未声明相应能力时沿用旧功能。客户端使用同一后端规则和现有认证下载通道。遇到一个码对应多个目标时，需要使用支持候选选择的页面核对，旧调用不能自动写入。

迁移前备份实际业务数据库。增量迁移重复执行不会清空表；代码回滚不得删除身份、来源或流水。产生单件数据后，不能直接运行不认识单件模型的旧代码继续数量操作，应停写核对并采用兼容修复。若需要恢复快照，先核对快照后的业务差异，再单独确认。

源码与软件测试不代表已上线或真机通过。正式部署、安装包、手机相机、实体扫码枪和打印机分别验收。

资产弹窗采用圆角边框及内部滚动；点击四周遮罩、取消或 Escape 可退出，保存提交期间暂不关闭。关闭扫码窗口同时释放摄像头。


## BOM／表格批量匹配与出入库

在物料管理顶部导航中进入与“物料仓库 / 我的借用”同级的 **表格批量** 页面。先上传文件，再配置字段映射、逐行编辑，最后选择操作方式和校区。支持 `.csv`、`.tsv` 和 `.xlsx`（每文件不超过 2 MiB、200 行）；旧版 `.xls` 请先在表格软件中另存为 XLSX。上传只在服务器内存中解析，不作为附件保存，也不自动修改任何库存。

页面首先展示原始列，可选择表头所在行，系统自动建议编号、名称、规格、数量、单位的映射，也可以手动调整并记住同类表头的选择。编辑区支持直接修改物料编号、名称、规格型号、每套／实收数量、单位，增删行；数量及编号／名称必须在库存匹配前补齐。变更列映射将根据原表重新生成行，覆盖已经手工编辑的内容。按 `M:<ID>` 内部物料标签、嘉立创 `C...` 编号优先匹配；无编号时再按名称与规格匹配。存在多个候选时必须人工选择，未匹配行可按已有物料 ID 指定，不能依赖名称模糊猜测后直接扣库存。

- **BOM 出库**：先编辑 BOM，再选择校区和出库方式，填写需要制造的 **套数**。系统按“每套用量 × 套数”计算总需求，跨行相同物料会合并库存需求、避免重复扣减。耗材登记为领用；可按数量管理的设备登记为当前成员的借用，必须归还。任何一种物料不足，整批出库拒绝，不允许只扣减前面几行。
- **表格入库**：在编辑后选择入库，根据每行数量批量增加已有数量物料库存，不受套数影响。管理员／项管／拥有资产管理权限的成员可以将未匹配行**明确选择**为“新建数量耗材”，提交时建档并入库（仅支持有效 C 编号自动绑定），普通成员只能给已有物料批量入库。
- **不兼容项目**：逐件管理设备需要单件身份核对；正在迁移的设备不能按旧数量登记；“充足／不足”管理的螺丝等自由取用耗材不按数量出库、入库。此类行会阻止提交，需要改用其原有工作台操作或从本次清单移除。

**提交前**需核对匹配的型号、可用库存、套数、校区和用途／入库原因。后台在事务中检查物料版本、库存版本、全部行数量，统一写入现有不可修改的资产流水；任一校验失败则整批回滚。网络超时或返回结果不确定时必须用**相同请求标识**重试，不能重新发起第二批。刷新后原资产页面会提示恢复上次待确认的登记。提交后的流水可从相应物料详情查看，原有借还规则不变。

建议把 Excel 中的“公式结果”预先保存好再上传，读取采用缓存的计算值，服务器不会计算公式，也不会执行宏。
