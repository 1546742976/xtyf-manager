# 按专业组排列与整组排期

任务中心选择一个造车组别后，默认按负责人专业组展示「机械 → 电控 → 视觉」。同阶段按开始日期、截止日期、任务 ID 排列，未设日期排在末尾。参与成员不会改变任务阶段；负责人没有对应专业组的任务显示在「未归类」。可以继续切换按人、按状态或任务树视图。

管理员和项管在任务管理的任务列表中选择造车组别，再点击「一键排期」。预览包含该车组全部任务，不受搜索或状态筛选影响；负责人同时属于多个相关专业组时，在预览中为任务选择一个阶段。选择会随应用排期保存，后续排序继续使用；负责人专业组变化导致原选择不兼容时，需要重新选择。

只有未开始、进行中和阻塞任务参与排期。同阶段任务可并行；最早存在的阶段保留原日期，下一阶段所有任务从上一阶段最晚截止日期开始，并保持各自原工期。如果没有电控任务，视觉阶段直接衔接机械阶段。日期直接使用上一阶段截止的当天，不额外增加一天，也不跳过周末。

例如机械阶段最晚截止日期为 2026-10-22；电控两项任务原工期分别为 2 天和 4 天，则开始日期都为 2026-10-22，截止日期分别为 2026-10-24、2026-10-26。视觉阶段从 2026-10-26 开始。

已完成、已取消、已删除及未归类任务不参与阶段衔接，保留原日期。参与排期的任务必须同时设置有效的开始日期和截止日期；有问题时，预览会列出任务并禁止应用。回到任务编辑补齐日期后重新预览。

确认变更清单后，点击「确认应用排期」。系统一次性保存整批调整，并写入各任务的版本记录和动态日志。预览后任务新增、删除、编辑，或负责人专业组变化，都会使预览失效；页面提示重新预览，本次不会保存任何调整。保存后没有持续自动联动，后续改期需再次一键排期。管理员可沿用任务版本记录逐项撤销修订。

## 接口与兼容性

- `POST /api/projects/<id>/schedule/preview`：JSON 可包含 `phase_choices`，格式为任务 ID 字符串到专业组名称的对象；返回车组、全部任务的原/新日期、阻止应用的问题、变更数量及签名快照。预览不修改任务。
- `POST /api/projects/<id>/schedule/apply`：提交预览返回的 `snapshot`。服务端核对完整车组任务及负责人专业组快照，再计算并原子保存；变化返回 HTTP 409。
- 两个接口均要求管理角色和有效 CSRF 凭据。应用不接受客户端自行指定的新日期。
- 第 4 版任务迁移新增可空的 `schedule_stage` 字段。原任务默认为空，已有日期不会被迁移自动更改；多组负责人手选的阶段在应用时保存。
- `/api/data` 为任务新增 `stage_options`、`owner_stage` 和持久化的 `schedule_stage`。普通任务编辑保留阶段选择，日期依赖提醒和父子关系继续使用原有机制。
