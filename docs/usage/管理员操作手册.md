## 2. 任务管理（`/manage`）

菜单：左侧「**任务管理**」（`/manage`）；独立的「**任务中心**」（`/tasks`）可浏览看板。

### 2.1 新建任务

填写表单后点「创建任务」：

| 字段 | 说明 |
|---|---|
| 任务标题 | 必填 |
| 负责人 | 下拉选择成员 |
| 组别 | 可以不填，选择负责人后自动带入其组别 |
| 项目 | 如：哨兵 / 轮腿步兵 / 狗洞步兵 / 重装步兵 / 靶车 / 宣传 |
| 优先级 | 高 / 中 / 低（看板上以颜色圈显示） |
| 状态 | 未开始 / 进行中 / 已完成 / 阻塞 / 已取消 |
| 开始 / 截止日期 | 截止日期决定看板上的"剩余天数" |
| 说明 | 任务的具体要求、当前情况 |

> 提示：进度百分比已取消，进度以"状态 + 剩余天数 + 更新备注"来体现，避免无法量化的问题。

### 2.2 任务列表

- 支持按 **搜索 / 组别 / 状态** 筛选，右上角显示"筛选后/总数"
- **剩余天数**列：随北京时间每天自动变化
- 操作：
  - 「编辑」：打开任务详情，可改授权字段（含改负责人、延期等）；只有管理员可改父任务关系
  - 「删除」：执行逻辑删除。任务会从常规列表隐藏，但日志、修订和附件元数据会保留；有未删除子任务或仍被其他任务依赖时会被拒绝。当前没有面向用户的恢复入口，删除前请确认范围。

### 2.3 导出

任务中心或任务管理页右上角「导出任务 CSV」：导出全部任务表格（含剩余天数、负责人/组别/项目/父任务/参与者/前置任务/版本等列），可用 Excel 打开。CSV 的列以逗号分隔；单个“组别”字段内有多个组名时，以分号分隔。系统会为可能被 Excel 识别为公式的单元格加保护前缀。

### 2.4 协作任务管理（实现完成，待部署）

协作功能实现和浏览器流程验证已经完成，仍待最终源码审查与生产部署。部署后，管理员、项管、负责人和参与者按以下规则操作：

| 事项 | 管理规则 |
|---|---|
| 组别 | 成员和任务都可关联多个组；导入 CSV 的列使用逗号分隔，单个组别字段内的多个组名使用分号分隔；导出保留原有列并转义会被表格软件当成公式的单元格。 |
| 项目 | 每个任务只能选择一个项目。项目用于归类与筛选，不能用多个项目字段替代任务树。 |
| 负责人/参与者 | 可指定一个总负责人和多个参与者；负责人或参与者可修改除 `parent_id` 外的所有任务设置。只有 **管理员** 可设置或修改 `parent_id`。参与者非空时必须有总负责人。新分配只能选择启用成员，既有历史记录会保留已停用成员。 |
| 树和依赖 | 创建或编辑时分别配置父任务和前置任务。禁止形成环；存在子任务或被其他任务依赖的任务不能逻辑删除。删除是逻辑删除，保留日志、修订和附件元数据，且没有用户恢复入口。依赖告警只是提示，不会自动调整开始日期。 |
| 修订与撤销 | 每次变更记录字段级前后值和版本。只有管理员可按某一修订撤销；如果之后已有人触碰同一字段，撤销应返回冲突，先核实后再手工处理。撤销不会删除备注或截图。 |
| 截图附件 | 参与者及管理角色可上传；仅上传者或管理角色可删除。单次最多 5 张、每张最多 10 MiB，仅 PNG/JPEG/WebP。上传失败时不得留下半条元数据或孤立文件。 |
| GitHub | 页面只提供配置好的 Issue/Discussion 外链；未配置时展示未设置状态。不要把真实账号、密钥、数据库、发票或附件提交到公开仓库。 |

### 2.5 上线前备份与恢复

协作升级会新增关系、修订和附件元数据，但不会重置成员、任务和日志。迁移在应用初始化时以版本记录和事务执行，可安全重复运行。**现有** `deploy/backup.sh` 每日备份进度/资金库、每周打包发票，但没有覆盖 `data/task_attachments/`，也没有把密钥和所有数据文件统一为一个恢复点；它不足以单独完成协作升级后的恢复。

生产升级前请由运维人员完成并记录以下操作：

1. 暂停应用写入；最稳妥的方式是停止 `rm-progress.service`。不要在写入仍进行时混合复制数据库和文件。
2. 在同一恢复点保存 `data.db` 及其 `-wal`/`-shm`、`data/funds/`、`data/invoices/`、`data/task_attachments/` 和 `secret.key`。停止服务后可整体复制；若使用 SQLite 在线备份 API，则必须在写入暂停期间对每个数据库备份，并复制同一时点的全部文件。
3. 先恢复到隔离目录，运行 `PRAGMA integrity_check`，核对成员、任务、日志、关系、附件元数据和附件文件清单，再允许切换服务。
4. 恢复时必须同时还原同一恢复点的数据库、附件、资金、发票和密钥；只还原其中一部分会造成关联数据不一致或无法解密既有会话。

## 3. 成员管理（左侧独立入口 `/members`）

### 3.1 添加成员

表单填写：姓名、组别、用户名（默认=姓名）、初始密码（留空则随机生成）、角色（**仅管理员**可选管理员/项管/成员）。

### 3.2 批量导入

在文本框里每行写一个人，格式：

```
姓名,组别
张三,机械
李四,视觉;电控
```

- CSV 列用逗号分隔；一个人的多个组别写在同一“组别”列中，并用分号分隔。第三段（用户名）可不填，默认用姓名
- 用户名重复时自动加数字后缀
- 批量导入的成员默认角色为「成员」，每人生成独立随机初始密码（请妥善保存结果并分别通知）

### 3.3 专业组字典（枚举式维护）

进入「成员管理」底部的「专业组字典」，可以新增组别或点击现有组别的「重命名」。首次升级自动预置 **视觉、电控、机械、硬件、宣传、运营**；预置只执行一次，以后自行重命名不会被重新生成旧名字。

- 添加成员、成员「编辑组别」、任务分配均可勾选多个组别，例如 **视觉 + 电控**；筛选任意组时会匹配属于该组的成员。
- 数据库采用稳定的组别 ID 与成员/任务的多对多关系（与枚举标志的 OR 效果相同，且改名不改变归属），不直接使用位掩码。
- 旧数据库若存在「视觉;电控」等历史拼接组别，首次升级时自动拆分为独立组别关联。升级前请备份 data.db。
- 管理员/项管可维护专业组字典，系统角色「成员/项管/管理员」仍单独决定访问权限，与专业组无关。

### 3.4 成员表格

- 支持 搜索姓名/用户名、按组别、按角色 筛选
- **角色列下拉框**（仅管理员可操作）：直接切换 成员 / 项管 / 管理员
- 「重置密码」：留空则生成新的随机密码并在界面中显示一次
- 「停用/启用」：停用后该账号无法登录（人员离队时用）

## 4. 资金管理（`/funds/`）

菜单：左侧「**资金台账**」。

### 4.1 添加记录

「添加记录」页签：

- 类型选「出」（支出）时，**去向、申请人、发票数目、处理人必填**
- **申请人自动填当前登录人**（也可以手动改，比如代别人记账）
- 提交后：
  - 如果添加人属于 **FUNDS_REVIEWERS** 中配置的审核人（默认 `chy`）：审核状态自动为「**已审核**」
  - **其他人添加**：审核状态为「**待审核**」，并提示"等待陈虹宇审核"

### 4.2 审核流程（重要）

- 记录管理表格里有「**审核**」列：
  - 🔴 待审核（红色）+「通过」按钮
  - 🟢 已审核（绿色）
- 指定的审核人登录后，顶部导航「资金管理」旁边会出现**红色数字角标**（=全队待审核数量），每 30 秒自动刷新
- 点某条记录的「通过」→ 状态变「已审核」，角标数字自动减少
- 历史遗留记录默认视为"已审核"，不影响

### 4.3 记录管理

- 筛选：类型（进/出）、关键字、金额范围、日期范围
- 排序：点「金额」「日期」表头切换
- 「编辑」（铅笔）：修改任意字段
- 「删除」（垃圾桶）：删除记录
- 资金台账页面标题区「导出资金 CSV」：导出当前筛选记录（含审核状态列）

### 4.4 统计图表

「统计图表」页签，点击按钮切换：月度收支 / 支出类别 / 队员支出排名 / 进账来源分布。右侧为统计摘要（进账来源 TOP5、队员支出 TOP5、类别支出 TOP5）。

### 4.5 数据同步

每次增删改后，系统自动同步生成 `资金管理记录.txt` 文本台账（含"审核"列），可以直接发给指导老师/财务备案。

## 5. 发票管理（`/invoices/`）

菜单：左侧「**发票中心**」；普通成员显示「**我的发票**」，管理员/项管看到的是全量视图。

### 5.1 全部发票列表

- 支持筛选：状态 / 月份 / 分类 / 提交人 / 日期范围 / 关键词搜索
- 每行操作：
  - **状态下拉框**：直接切换 未报销 / 正在报销 / 已报销（切换为已报销/正在报销时，PDF 文件会自动移动到对应文件夹）
  - 「打开」：浏览器预览 PDF
  - 「编辑」：详情弹窗，可改 状态、报销日期、提交人、类别、备注、发票号码、标签；也可「清除元数据」

### 5.2 批量操作

勾选多张发票（表头可全选）→ 出现批量栏 → 批量改状态 / 批量设提交人 → 「执行」。

### 5.3 顶部功能按钮

| 按钮 | 作用 |
|---|---|
| **统计** | 全部发票的总数、总金额、状态/月份/类别/提交人分布图 |
| **导出CSV** | 导出全部发票明细表（含文件路径等） |
| **导出压缩包** | 把服务器上全部发票 PDF 打包成 zip 下载（含元数据，不含"往届发票.zip"） |
| **查重** | 按发票号全库扫描重复，确认后可删除多余副本（每对保留一张） |
| **整理文件** | 把散落在非标准文件夹的 PDF 归档到 `月份/状态` 目录并标准化命名（有预览确认） |
| **刷新PDF金额** | 重新从 PDF 文件里提取金额（带实时进度条） |

### 5.4 成员上传的发票怎么处理

- 所有成员都可以上传发票（提交人自动记为其本人，状态固定"未报销"）
- 成员只能看到自己上传的发票；你（管理员/项管）能看到**全部**
- 收到成员上传后，你的处理流程：
  1. 在列表里按「提交人」筛选找到该成员的发票
  2. 核对金额/发票号
  3. 走报销流程时把状态改为「正在报销」，打款完成后改为「已报销」

### 5.5 文件与命名规则

- 存储结构：`数据目录/{月份}/{状态}/`，例如 `2026.10/未报销/其他-98.8元-广东铨洲科技-264420...-2026.10.10-发票.pdf`
- 元数据（提交人/状态/备注等）存于 `.invoice_meta.json`，金额缓存存于 `.invoice_cache.json`
- 上传时自动按发票号查重；重复会拦截并提示

## 专业组与造车组别（2026-10 变更）

为避免混淆，**专业组**只描述成员的技能方向（视觉、电控、机械、硬件、宣传、运营）；**造车组别**描述实际参与的车种（步兵、哨兵、重装、飞镖等）。一个成员可以同时属于多个专业组、多个造车组别。任务只归属一个造车组别，不根据任务负责人自动关联专业组。

- 「成员管理」可分别勾选及编辑这两种组别，并能按其中任一种筛选成员。底部两个字典均可新增、重命名。
- 「任务管理」中的「造车组别」为任务归属；「任务中心」也只按造车组别筛选，不再显示任务专业组选择。
- 原有「轮腿步兵」「狗洞步兵」「重装步兵」等任务组别保留，不擅自合并到「步兵」或「重装」；可按需要手动重命名整理。
- 成员导出 CSV 分别列出专业组、造车组别；任务导出的「组别」指造车组别，旧「项目」列仍为兼容保留。
- v3 迁移首次运行时从任务负责人和参与者推断历史造车组别成员关系，仅执行一次。部署前备份 data.db 及相关文件。
