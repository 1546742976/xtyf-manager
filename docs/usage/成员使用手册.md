# 成员使用手册

适用对象：所有已登录成员。说明对应当前源码；线上页面是否已经更新，请以部署版本为准。

## 进入工作台

使用超级管理员提供的实际访问地址与登录用户名、初始密码。新成员初始密码由超级管理员单独告知；新建或重置的账号首次登录会强制进入 **账户设置** 改密，设置与初始密码不同的新密码后才能进入工作台。忘记密码时联系超级管理员或项管重置，不要在群聊中发送密码。

左侧导航按权限显示：工作台、任务中心、协作、我的发票、账户设置；超级管理员和项管还可以看到任务管理、成员管理、资金台账等。

## 账户设置（`/account`）

- **头像**：在电脑或手机浏览器的“个人信息”卡中选择“更换头像”，拖动图片、使用缩放滑块或方向键／方向按钮调整圆形预览，再保存。支持静态 JPEG、PNG、WebP，单张不超过 10 MiB、2000 万像素、单边 10000 像素。取消不上传；失败可保留裁剪结果重试，不影响正在编辑的个人资料。保存后账户页、侧栏、顶栏同步更新，其他设备刷新后生效。“恢复默认头像”重新显示姓名首字。首次登录须先改密；当前客户端暂不提供头像编辑入口。

- **外观**：在顶栏外观菜单或账户设置选择四套亮色／四套暗色主题，或跟随系统；亮暗配色分别记忆，点击后立即切换并保存到账户。其他设备下次打开或刷新页面时同步，不影响已登录会话。保存失败时恢复原主题，可点击重试；首次登录先完成改密。
- **可以修改**：自己的登录用户名、所处专业组（多选）、参与造车组别（多选），以及验证当前密码后修改密码（新密码至少 8 位）。
- **不能修改**：成员 ID、真实姓名、系统角色或自己的启停状态。需要修改姓名请联系超级管理员。
- `members.id` 是系统内部稳定的数字身份标识，**不是登录用户名**；更换用户名不会产生新账号、也不会改变任务归属。旧用户名在修改后不再能登录。

## 专业组和造车组别

| 类型 | 含义 | 示例 |
| --- | --- | --- |
| 专业组 | 人员技能与分工，可多选 | 视觉、电控、机械、硬件、宣传、运营 |
| 造车组别 | 参与的机器人/车种项目，可多选 | 步兵、哨兵、重装、飞镖及自定义 |

**任务只归属一个造车组别**。例如同一位视觉成员可以同时参与步兵和哨兵任务，任务不会被自动归到“视觉”。

## 工作台和任务中心（`/`、`/tasks`）

按人视图不显示超级管理员任务栏。未分配任务位于筛选栏下方最上方，卡片横向排列，遵循当前筛选；没有匹配的未分配任务时整块隐藏。账户设置中的「外观」位于「个人信息」下方。
专业组视图使用时间轴，每个任务独立一行，显示负责人、状态及起止日期；同日任务用标记展示，缺失或非法日期显示文字说明。筛选保留当前车组的时间坐标。手机上显示纵向阶段列表；点击任务或用键盘打开详情。
选择单一造车组别后，任务中心默认按负责人专业组展示「机械 → 电控 → 视觉」，也可切换其他视图；未归类任务单独展示。专业组不决定排期先后，一键排期按具体前置约束、默认只顺延并保留原工期。可在任务编辑中勾选“自动排期时固定日期”；实际应用后可在日期和版本记录查看结果。操作规则见 [任务排期](任务排期.md)。

- 查看任务概况，切换 **按人 / 按状态 / 依赖图**。
- 可以按造车组别、状态筛选，也可搜索任务、切换“只看我的”、手动刷新和导出任务 CSV。
- 点击任务查看标题、总负责人、参与者、状态、优先级、日期、说明、更新历史、依赖与截图等。
- **总负责人和参与者**可以编辑本人负责／参与任务的一般设置、进度及主前置任务和其他前置依赖；超级管理员与项管可编辑所有任务。创建者还可维护标题、说明及计划日期，但不会因此获得执行或改派权限；其他成员可查看，不能借 API 越权修改。撤销任务修订仍仅限超级管理员。
- **主前置任务**与其他前置任务共同表示当前任务的上游依赖，不表示任务包含关系。依赖图箭头从前置指向后续任务。新建时根据主前置结束前 2 天预填开始日期，且不早于其开始日，手动修改后不再替换。保存后的日期不自动跟随；可点击“重置为依赖时间”重新取一次建议。所有前置的日期提醒都遵守相同的两天衔接规则。
- 保存前如别人已更新该任务，可能提示版本冲突；刷新详情、确认新版本后再改，勿用旧表单覆盖。
- 截图留痕：支持 PNG/JPEG/WebP，单次最多 5 张、每张不超过 10 MiB；文件需要登录并经权限检查，上传者或管理角色可以删除。
- 任务删除是**逻辑删除**，不等同于成员或组别的可恢复归档：当前没有任务恢复的用户入口。

## 一键排期（造车任务）

超级管理员和项管在任务管理页点击“一键排期”。未筛选组别时先选择一个造车组别；已筛选时直接预览该组。空组会提示先在任务中心创建任务，创建时须选择对应造车组别。

1. 读取该组全部未删除任务及其前置依赖，不受搜索、状态筛选影响；不会修改其他组的任务。已完成和已取消任务不调整，进行中和固定日期任务默认不调整，可明确勾选允许本次调整。
2. 基准日期默认为北京时间今天。已有有效起止日期的任务沿用原工期，按自然日计算、包含首尾；日期不完整的任务需要填写正整数工期，再点“更新预览”。
3. 按前置关系从前往后计算。默认建议在前置结束前两天衔接，但不早于前置开始；多个前置取最晚的衔接下界。前置已完成时优先使用实际完成日期，缺失则提示并退回计划截止日期。
4. 默认只顺延，不把已有日期提前。已经保存的更早准备日期允许与前置重叠，仅提示人工预留，不会强制挪到两天衔接日。机械、电控、视觉仅为展示分类，不自动生成先后关系；没有前置关系的任务可以同时开始。同一负责人任务重叠只提醒，不会自动按人力排队。
5. 查看原日期、新日期和冲突。修改参与任务、基准日期或工期后，必须更新预览。依赖环、前置失效或缺少必要日期等冲突会阻止应用；没有实际日期变化时不能重复提交。
6. 点击“确认应用排期”才保存。服务器核对预览以来任务和依赖是否变化，有变化则要求重预览；全部日期、版本和历史记录在同一事务提交，失败整批回滚。确认后不持续自动联动。

例如：A 的计划为 10 月 24 日至 30 日，B 以前置 A 衔接、工期 3 天且无已保存的更早日期；基准为 24 日时，B 可安排在 28 日至 30 日。两天重叠是当前业务规则，并非必须等 A 完成后才开始。

## 我的发票（`/invoices/`）

1. 上传 PDF 发票，检查系统读取到的发票信息和重复提示。
2. 按页面流程确认暂存文件入库；非管理角色的提交人按当前成员身份记录，不能代替别人提交或自行切换报销状态。
3. 在列表中查看本人发票、状态、金额和文件预览；如归属不正确，联系财务负责人处理。
4. “未报销 / 正在报销 / 已报销”的业务流转由有财务管理权限的人维护。识别结果可能不准确，以票据原件及人工复核为准。

发票列表与预览在服务端按成员 ID 校验归属；历史无法明确归属的票据由财务人工确认，姓名不作为访问权限证据。

上传确认时修改的日期、供应商及金额会保留为确认值；空日期或供应商表示未知。批量确认失败的条目保留暂存文件，可修改后重试。重复提示只展示类型，不会公开其他成员的文件路径。

## 协作（`/discussions`）

全员可以发起话题、回复和上传任意格式文件。标题最多 120 字，正文最多 5000 字；每条最多 5 个文件、单个 100 MiB、总计 180 MiB。图片提供安全缩略图，其他文件下载查看。

消息不可编辑；作者可在不足 120 秒内撤回，整话题还要求无回复。超级管理员、项管可随时撤回。撤回后显示占位，原件在服务器长期保留，站内停止提供。切换话题保留本页草稿；发送失败保留文字及文件，超时会先核对结果，手动重试不重复发帖。未读按账户同步，阅读旧消息不强制跳到底部。

详见[本地协作使用及存储说明](../technical/本地协作.md)。此功能不连接 GitHub，不改变 22:00 项目晚报。

## 常见问题

- 登录失败：核对用户名与密码。短时间多次失败会触发限流；由超级管理员执行密码重置。
- 找不到管理按钮：这通常是角色权限限制，不是页面故障。
- 任务或组别没有显示：检查筛选条件；已删除/归档记录可能只允许超级管理员查看。
- 页面内容与本文不同：可能尚未部署最新 `main`；请先核对服务器实际版本，不要直接用文档推断生产能力。

## 任务中心与首页目标

任务中心顶部可切换“造车任务”和“日常项目”。日常项目按所选专业组分别更新，与造车任务分开管理，历史备注、图片和负责人保留。旧项目链接和邮件链接仍可打开。

所有已登录、启用且完成首次改密的成员（含普通成员、项管、超级管理员）在两个标签页均可使用“新建任务”按钮，弹窗内选择造车任务或日常项目，默认当前标签页类型。切换类型、关闭后再打开以及保存失败时，当前页面内未提交的内容保留；刷新页面不会保留草稿。编辑已有日常项目时类型固定，仍由超级管理员或项管操作。分组负责人可按姓名或专业搜索，多选状态会显示已选人数，启用的超级管理员也可作为负责人候选。普通成员可选择已有造车组别，不能借创建任务新增组别字典。

首页配置目标后显示剩余天数；当天显示“今天”，过期显示“日期已过”。日期按北京时间计算，只有超级管理员可以配置。侧栏外观按钮切换到记忆的另一种亮暗配色，并退出跟随系统。


## 任务推进规则（2026-10-18）

已完成与 100% 进度同步，重新打开须填写真实进度；日常项目在全部启用组达到 100% 后完成。详情中可维护阻塞原因、下一步和处理结果，并关联协作话题及结论。管理角色可通过工作台的“团队异常”集中处理问题。具体权限、历史兼容与操作步骤见[任务推进与异常处理](任务推进与异常处理.md)。

## 2026-10-22 输入与附件规则

- 任务标题最多 200 字符、描述 10000、截图说明 500；成员姓名和用户名各 64。
- 资金类别 64、来源/去向 200、申请人/经手人各 64、备注 2000；日期必须有效，错误保留输入并显示中文原因。
- 讨论正文最多 20000、标题 120；附件每个 25 MiB、每条合计 60 MiB、每成员累计 512 MiB。已撤回但服务器仍保留的附件也计入配额。
- 任务和日常图片仍最多 5 张、每张 10 MiB。请求整体限额不是单文件限额。
- 发票确认金额按分舍入后必须大于零。所有上传人仍可人工补录；批量失败项保留，不能以 0 元占位入库。
- 已登录但无管理权限时显示中文 403；未登录仍先进入登录。登录受限时按提示等待，不连续重试。
- 发票列表显示上次完成更新的时间与忙碌/失败状态；首次未就绪会提示初始化，不代表没有发票。


## 协作成员简介

整个讨论区下方的“成员简介”独立展示已填写资料的有效成员，支持姓名、组别搜索及分页。协作页“编辑我的简介”和账户页编辑同一份资料，不影响原话题和消息草稿。

简介为最多 1000 字的纯文字，可换行；可选填最多 3 个 GitHub 个人主页和 3 个仓库地址，每条可填写最多 200 字的简单介绍。主页格式为 `www.github.com/用户名`，仓库为 `github.com/所有者/仓库`。也接受带协议的地址，点击链接统一使用 HTTPS；重复地址不重复添加。系统不验证账号归属，不读取 GitHub 内容，也不需要 Token。简介和两组链接全部留空后不再列出卡片。账户页个人信息卡片直接预览已保存内容，保存后立即更新；协作页展示同一份资料，其他已打开页面刷新后读取最新内容。

已有个人主页会作为第一条主页保留；旧仓库资料仍保留在本人编辑器“查看原仓库资料”中，不自动公开。需要展示时，请核对后添加到仓库列表。旧客户端保存旧资料不会清空新增链接；旧单主页客户端仅修改第一条主页，其余链接保留。新界面遇到不支持多链接的服务器时提示升级，不提交不兼容资料。

所有登录成员可查看，只有本人可编辑。超级管理员、项管可以带原因隐藏或恢复整份简介，不能代改内容。隐藏后本人仍可编辑，但保存不解除隐藏。出现版本冲突时草稿保留，可先查看最新资料及隐藏原因，核对后选择使用最新版本再保存。旧服务器不支持时会提示功能尚不可用，原协作功能照常使用。

## 超级管理员权限

内部角色仍为 `admin`，所有现有及以后设置为该角色的账号自动拥有全部已定义管理权限，包括资金审核、发票管理和资产管理。权限页显示“角色自带、不可单独撤销”；需要取消角色权限时应调整角色，原有独立授权仍按原规则处理。停用、删除、首次改密和会话失效限制照常生效，超级管理员也须遵守业务一致性、审计和仅本人编辑简介的规则。项管和成员的独立授权规则保持不变。
