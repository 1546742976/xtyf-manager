# PR #60 评论修复验收

## 行为与回滚

- 发票仅在通过权限及业务校验、即将写元数据或移动文件时开始快照更新。结束时比较原始元数据及触及文件的存在性/inode/大小/mtime，只有实际变更才发布一次；拒绝和完全补偿不扫描。部分提交后 500 仍发布已提交内容，但状态保持 failed。手动刷新复用刚完成的扫描。
- 资金新增 `funds_ledger_state` 单行状态及 records 三个变更触发器：版本与业务记录同事务递增。TXT 成功替换后记录其对应版本；同步期间发生新写入时仍为 pending。状态保存在原资金数据库，进程重启不会丢失，既有启动同步可修复。
- GET `/funds/api/ledger-sync` 显示同步状态；POST 需要原资金审核管理权限，只重建 TXT，不新增或改变资金记录。失败保留 pending/failed 并记录异常类型，不保存财务正文。页面提供持续状态及“重新同步台账”。原 request_id 和旧客户端升级门禁不变。
- 回滚本提交保留数据库、请求回执和台账；不执行删表迁移。旧代码不会消费新状态，重新升级后启动同步会刷新它。
