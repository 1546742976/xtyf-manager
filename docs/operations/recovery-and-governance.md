# 恢复演练与可靠性治理准备

本文件是待运维执行的准备资料，不代表生产演练、代理启用、客户端发布或真机验收已完成。
配置边界见 [来源识别与进度连接](reliability-boundaries.md)。本轮不自动安排备份或清理数据。

## 生产恢复演练

1. 系统负责人确认恢复授权、可接受的 RPO/RTO、维护窗口、业务核对人及中止后的联系渠道。
2. 盘点实际主库、资金库、发票目录及元数据、头像和附件目录、会话密钥的位置。
   自定义环境路径必须与快照工具的覆盖范围逐项比较；有范围外路径就中止，不能宣称“完整备份”。
3. 停止入口写入、应用服务、队列消费者和相关定时写任务；确认无另一个实例或人工脚本写入。
   不在运行中的目录直接复制 SQLite 主文件代替一致性快照。
4. 使用 `deploy/consistent_snapshot.py create --app-dir <实际目录> --output <受保护快照路径> --offline-confirmed`。
   `--offline-confirmed` 只在人工确认全部写入已停止后使用；不能为绕过检查而填写。
5. 执行 `verify --archive <快照>`，记录时间、清单、哈希、工具/源码版本；限制快照访问并加密异地副本。
   加密工具、异地位置、密钥保管人与保留期由运维确认，本轮不引入自动任务。
6. 执行 `restore --archive <快照> --target <全新空路径>`。不覆盖现有部署；旧目录保留用于中止恢复。
7. 在隔离网络关闭真实邮件及外部写集成，检查两库 `integrity_check`、外键、文件哈希和业务引用。
   核对资金回执仍能阻止重复新增，发票归属和元数据、头像、图片附件均可读取；验证登录、权限和待处理队列。
8. 业务核对通过后才能提出切换申请；记录实际数据损失窗口和恢复用时。生产切换单独授权。

中止条件：哈希或完整性失败、目录漏项、未知写入者、存储不足、权限异常、密钥不匹配、回执/附件引用缺失、
待发邮件可能误发、业务核对不一致。保持停写，保留原数据与失败日志，不自动覆盖或删除。

## 时间语义清单（只核查）

| 数据/用途 | 当前实现及语义 | 后续决策 |
|---|---|---|
| 通用记录与审计 created_at | `common.now_str()`：服务器本地无偏移字符串 | 确认历史部署时区与变更记录，不能假定所有字符串都是 UTC 或北京时间 |
| 资产流水 | `modules/assets.py::stamp`：显式 UTC+8 字符串 | 保留用户登记时间与服务器提交时间的区别 |
| 完成时间与任务剩余天数 | `task_mutations.completion_stamp`、`task_queries.task_data`：北京时间 | 日历截止日不按 24 小时秒数计算 |
| 日常/邮件日期 | `mail_service` 使用显式北京时间；部分通用创建记录仍来自 now_str | 逐字段标注，不能整库平移 |
| 资金审核与文本更新时间 | `funds.py` 使用本地 datetime；record_date 是业务日历日期 | 审核发生时刻与用户业务日期分开治理 |
| 发票后台队列 | `invoice_jobs.py`：Unix 秒 | UTC 瞬时语义；与无时区字符串不可直接比较 |
| 登录窗口 | `app.py`：Unix 秒，持久化计数 | 时钟大幅跳变仍需现场时间同步与告警策略 |
| SSE 寿命、审计限频、进程等待 | monotonic 时钟 | 不能落库当业务时间或跨进程比较 |
| 审计保留边界 | security.cleanup_audit_rows：本地 now 减天数后按字符串严格小于比较 | 容量优先与引用豁免继续有效，关闭清理不恢复已删记录 |
| 导出文件名/统计日期 | app.py 部分导出使用主机日期 | 明确是否只作展示，统一方案另行确认 |

固定时刻回归涵盖 UTC 15:59:59/16:00 的北京时间跨日、跨月/跨年、闰年日历及清理边界。
未来建议：日历日期保留 YYYY-MM-DD；新增“发生时刻”协议采用带时区或 Unix 时间；显示层按业务时区转换。
需先形成字段映射、历史来源证据和兼容迁移方案，再修改新写入行为。未知历史偏移应保持未知，不猜测补齐。

## 密钥轮换清单

只核对用途、路径配置和权限，未读取或保存真实密钥内容。

| 类型 | 轮换注意事项 | 负责人待确认 |
|---|---|---|
| Flask 会话密钥 | 轮换会使现有会话失效；备份、登录恢复和依赖该密钥的验证链需单独核对 | 服务负责人 |
| 页面资源发布签名 | 新旧公钥交接必须先考虑已安装客户端；保留发布序号反重放，不能用降序发布回退 | 发布负责人 |
| Android 正式签名 | 替换身份可能无法覆盖安装；核对既有证书指纹、账号/密钥恢复方案，不生成替代密钥冒充原身份 | 客户端负责人 |
| SMTP 凭据 | 暂停/核对发送队列，轮换后只向批准的测试收件人验证；结果不明不自动重发 | 邮件管理员 |
| TLS/SSH/部署凭据 | 验证证书链、主机身份、撤销旧凭据与最小权限；上线窗口独立确认 | 运维 |

## 留存决策（本轮不清理）

| 资料 | 当前安全约束 | 待业务确认 |
|---|---|---|
| 资金幂等回执 | 编辑/删除账目后仍保留，旧请求不能重新新增 | 保留期限必须覆盖可能重试的客户端；不能直接按账目删除 |
| 安全审计 | 90 天/10 万行策略及任务引用链豁免已存在 | 业务审计要求、容量预算、归档与访问人 |
| 发票/讨论/任务附件与头像 | 文件、归属与业务引用共同恢复；撤回但仍保存的附件继续计费 | 删除申请、保留期、备份中的删除传播 |
| 浏览器待确认请求 | 按服务器及账号隔离，刷新可重试原请求；浏览器清理会丢失恢复线索 | 共享设备提示、退出后的留存说明、人工核对流程 |
| 测试诊断 | 仅合成账号 ID/状态/会话版本，不含密码或 Cookie | 本地诊断保留期，CI artifact 访问和清理 |

## 告警与处置设计（未接入通知）

| 信号 | 可观测入口 | 建议处置 |
|---|---|---|
| SSE 额度拒绝 | `/invoices/api/job/stream/` 的 429，JSON reason=sse_capacity；现有 Gunicorn access log | 检查旧客户端/多标签页和连接回收，推广轮询页面；不要只扩线程 |
| 登录/API 延迟 | 独立探测 `/login` 及认证只读 API 的耗时/超时 | 先查线程、DB 写锁、磁盘和资源压力，保留现场数据 |
| 台账同步失败 | `stage=ledger_sync`、记录 ID、request_id；响应 ledger_sync=failed | 记录已入库，不新建重发；检查权限/磁盘/锁，按原回执重试同步 |
| 部署健康失败 | 脚本非零状态与失败阶段、服务状态及 journal | 暂停发布后续步骤；确认是否已更新，人工核对，不自动删数据回滚 |
| 备份失败或过期 | snapshot 工具非零状态、最后一次验证成功时间与清单 | 保留原备份，停止覆盖；处理空间、权限及停写问题，再演练恢复 |

告警阈值、观察窗口、接收人和响应时限须由负责人结合真实在线量确认。
现有源码没有自动通知渠道；日志存在不等于已经有告警。

## 现场验收与待决策

- 运维：HTTPS 最终地址/证书链、每层代理真实来源及防火墙；真实 NAT 出口连带限流评估。
- 业务负责人：RPO/RTO、留存期限、恢复切换权限与停写窗口。
- 客户端负责人：Windows WebView2、Android、Ubuntu/Fedora 原生登录/上传下载、断网恢复、页面更新。
- 使用者：真实相机权限、扫码枪焦点、打印机实际纸张与标签；模拟浏览器不得替代真机结论。
- 维护者：依赖告警分级处理与升级窗口、测试偶发失败的首次现场日志、监控责任人。
