# 全项目审查修复（2026-10-14）

本文记录代码和隔离验证状态，不表示生产服务器已经发布。

## 第一批：安全与财务正确性

- 发票列表使用事件委托和原始路径，消除文件名进入内联 JavaScript 的脚本注入及重复 URL 编码。
- 发票确认与修改在写入前校验文字、日期、月份、状态和标签类型；批量确认按项返回错误并保留失败项临时文件。
- 普通成员所有重复响应仅返回类型，不暴露其他成员的文件路径。
- 资金库独立增加 `version` 列。查询和写入返回版本；实际编辑和审核递增，等值编辑不递增。
- 审核请求必须为 `POST /funds/api/records/<id>/review`，JSON `{"version": 1}`。缺失或非法版本返回 400，过期版本返回 409，不存在返回 404；冲突后刷新并由审核人再次确认。

第一批隔离回归：29 项后端测试、6 项前端测试通过。Windows 测试进程退出的 SQLite 清理问题将在第三批修复。

## 第二批：发票数据与操作

- 整理及预览以完整相对路径定位元数据；同名和多层目录移动保留归属、人工金额、状态、日期、供应商、标签和缓存。
- 新确认值 `confirmed_date`、`confirmed_vendor` 优先用于显示、搜索、文件名和 CSV；字段缺失沿用历史解析，明确空字符串表示未知。
- 特殊字符路径只在构造 URL 时编码一次，继续执行文件归属校验。

第二批隔离回归：32 项后端测试通过，包括同名嵌套目录、重复整理、确认值与 CSV、特殊字符预览及越权拒绝。

## 发布约定

升级前停止写入，制作完整离线快照并演练恢复。后端、前端必须同批发布；旧页面需刷新。资金版本迁移不改变现有记录 ID、金额和审核状态。

历史数据不自动猜测归属、金额或报销状态；已经丢失的信息须依据备份或管理员确认恢复。
