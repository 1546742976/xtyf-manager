# 任务流程与成员简介交付记录

基线：`34b4446`，分支 `codex/assets-serialized-ui`。仅本地源码交付，不部署、打包、改版本或操作真实库存。

## 第一批：任务权限与流程

- 所有有效登录且完成首次改密的成员可创建两种任务。创建者新增标题、说明和计划日期编辑权，不获得执行和归属管理权限。
- 日常任务增量记录 `created_by`；旧记录保持未知。新增日常修改流水，不回写历史业务数据。
- 执行者可带原因取消和显式重开；日常仅可重开本人负责组。终态进度接口拒绝隐式重开；管理纠错须说明原因。
- 两种任务默认优先级统一为中；网页及客户端共享表单。
- Windows Python 3.11.8：专项 40 项通过；相关 JS 8 项通过；新增反例先观察失败再修复。测试使用临时数据库，无真实邮件。
- 后续批次补充浏览器、全量测试和客户端构建结果，不将静态检查当作原生运行验收。

代码回滚使用对应提交的 `git revert`。保留增量字段与历史记录，不执行破坏性逆迁移。

## 第二批：指派邮件

新增独立 `assignment` 队列类型和个人开关（默认开启），与任务更新同事务入队，使用类型、任务 ID、版本、收件人去重。旧偏好请求保留新开关；发送时复核有效账号、邮箱代次、暂停、偏好、24 小时有效期和当前执行名单。SMTP 结果不明沿用 unknown，不自动重发。

Windows Python 3.11：`python -m unittest test_assignment_mail test_daily_mail` 53 项通过；Ruff 和 email.js 语法检查通过。新测试全部使用合成账号和模拟传输，未发送真实邮件。摘要邮件回归改为按被测邮件类型计数，避免将新增指派邮件误算为摘要。

## 第三批：成员简介与整体验证

新增 `member_introductions` 存储及登录保护接口：

- `GET/POST /api/account/introduction`：仅本人读写，完整字段与版本白名单。
- `GET /api/collaboration/profiles`：有效成员公开投影，姓名／组别搜索，独立每页 12 人。管理人员可包含隐藏资料；隐藏后清空仍可找到并恢复。
- `POST /api/collaboration/profiles/<id>/moderation`：管理员、项管带原因隐藏／恢复，版本同时递增，不能代改正文。
- `GET /api/collaboration/profiles/<id>/avatar`：现有头像的认证读取，隐藏后仅本人及管理人员可读。

网站及客户端共享账户／协作编辑器；纯文字简介 1000 字，最多 10 个规范化 GitHub 仓库，不读取外部仓库。失败保留草稿，冲突先展示最新资料与隐藏状态，再由用户确认采用新版本重试。默认卡片不公开邮箱、用户名等管理字段。旧服务器的 404 独立提示，不影响协作。

整体验证还修复日常完成后即时切换重开入口、简介提交时旧成功提示残留。既有终态测试调整为显式原因／纠错，不删除原完成时间、版本冲突和组进度断言。
