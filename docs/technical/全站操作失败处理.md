# 全站操作失败处理与验收

验证日期：2026-10-15。基于 `main` 的 `0e54662`，本次修改保留在本地工作区，未推送或部署；Team Management stash 未恢复。

## 用户行为

- 登录、账户、任务、成员、资金、发票、权限和主题使用共享请求层 `static/business-ui.js`。原有 CSRF 校验、权限接口和服务端业务规则不变。
- 普通 JSON 请求最多等待 15 秒；FormData 上传和下载最多等待 180 秒。发票 XHR 上传保留进度反馈，并处理超时、中断和错误响应。
- 保存、删除、审核、上传确认等提交等待期间防止重复操作；结束后恢复原按钮状态。失败时保留表单输入，不显示成功提示、不提前删除记录。
- 网络断开、超时或响应格式异常后，写入结果可能未知。提示用户先核对数据，再手动决定重试；不自动重放写入请求。
- 401 保留当前页与输入，提供新标签页登录入口。403、409、429 和服务端错误显示可读反馈；现有强制首次改密流程继续生效。
- 主题保存失败恢复原主题并提供重试；发票状态和成员角色修改失败恢复原选择。任务版本冲突继续使用已有的冲突提示和刷新机制。
- 发票上传确认失败保留待确认数据；部分失败保留失败条目、金额和提交人等输入。提交人加载失败保留上传文件并提供重新加载按钮。发票详情保存期间不可通过遮罩关闭弹窗。
- 发票整理预览失败不会启动整理。统计或详情读取失败不显示成功空状态。后台任务继续使用既有 SSE 和结果查询；失败结果保持可查看。
- 下载先检查 HTTP 响应，再交给浏览器保存；下载失败保留当前页面。退出登录请求失败也保留当前页面并恢复按钮。
- 错误反馈使用 live region；共享通知可关闭，长错误文字在手机宽度内换行。侧栏账户卡右侧的主题按钮与账户外观设置共用保存、回退和重试逻辑。

## 验证边界

这次验证了共享失败机制及上述业务路径，没有穷举每个按钮与每种错误的全部组合。手机结果来自浏览器引擎模拟，不等同于真实 iOS Safari 或 Android Chrome 验收。未执行生产网络、真实 GitHub 服务、Staging UAT、生产发布或整套后端回归。文件下载交给浏览器后，操作系统保存失败或用户取消保存不由网页判断。
