# 巡天御风管理系统 · 异地电脑接管与并行控制指南

面向对象：需要从其他电脑维护/开发树莓派的人员
最后更新：2026-10-12

---

## 1. 前提条件

| 条件 | 说明 |
|---|---|
| 网络 | SSH 只开放在**实验室局域网**（SSH 未通过 frp 暴露到校外）；新电脑需连接 SKYWALKER Wi-Fi |
| 地址 | 树莓派固定内网地址 `192.168.2.16`（路由器已做 DHCP 保留）|
| SSH 客户端 | Windows 10/11 自带 OpenSSH（`ssh` / `scp` 命令直接可用）|

> 当前只有陈虹宇的电脑持有 SSH 私钥。新电脑接入方式二选一（推荐方案 A）。

---

## 2. 方案 A（推荐）：新电脑生成自己的密钥

不传递私钥，安全性最好：

```powershell
# 1) 新电脑生成密钥（一路回车，不要设密码短语也行）
ssh-keygen -t ed25519 -f "$env:USERPROFILE\.ssh\xtyf_pi" -N '""' -C "新维护者名字"

# 2) 打印公钥内容
Get-Content "$env:USERPROFILE\.ssh\xtyf_pi.pub"
```

把打印出来的公钥（`ssh-ed25519 AAAA... 新维护者名字` 一整行）发给管理员（陈虹宇），管理员在树莓派上执行：

```bash
echo "把公钥整行粘贴在这里" >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
```

之后新电脑即可登录：

```powershell
ssh -i "$env:USERPROFILE\.ssh\xtyf_pi" xtyf@192.168.2.16
```

## 3. 方案 B：复制现有私钥

把陈虹宇电脑的 `C:\Users\陈虹宇\.ssh\rm_progress`（私钥文件，无后缀）复制到新电脑的 `%USERPROFILE%\.ssh\` 下，然后：

```powershell
ssh -i "$env:USERPROFILE\.ssh\rm_progress" xtyf@192.168.2.16
```

注意：
- 私钥等同于服务器密码，**用 U 盘/加密渠道传输，不要发微信/QQ**
- 多人共用一把私钥无法区分操作者，且泄露后要全体更换；仅临时应急使用

## 4. 推荐工具与工作方式

### 4.1 VSCode + Remote-SSH（最推荐，直接在服务器上写代码）

1. VSCode 安装扩展 **Remote - SSH**
2. `F1` → `Remote-SSH: Open SSH Configuration File`，添加：
   ```
   Host xxtyf-pi
       HostName 192.168.2.16
       User xtyf
       IdentityFile ~/.ssh/xtyf_pi
   ```
3. 点击左下角绿色按钮 → Connect to Host → `xtyf-pi`
4. 连接后打开 `/home/xtyf/progress_system` 直接编辑、内置终端跑 `bash deploy/deploy.sh`

### 4.2 文件传输

- **WinSCP / FileZilla**（SFTP，用同样的密钥和地址）
- 命令行：`scp -i 密钥 本地文件 xtyf@192.168.2.16:目标路径`

### 4.3 日常终端

Windows Terminal / PowerShell 直接 `ssh`；或 VSCode 内置终端。

## 5. 并行控制（多人/多电脑同时操作）

**可以同时连接**，SSH 支持多会话并发，互不影响。但注意以下约定：

| 场景 | 风险 | 约定 |
|---|---|---|
| 同时改同一份代码 | 互相覆盖 | 分工按文件划分；改动前在群里说一声 |
| 同时执行 `deploy.sh` | rsync 同步冲突（后执行者覆盖先执行者刚上传的源码）| **部署统一由一人执行**（建议陈虹宇）|
| 同时改数据库（SQL）| 数据冲突 | 禁止手改线上数据库；数据操作走网页 |
| 重启服务 | 短暂（约 3 秒）中断 | 尽量避开活动高峰；重启前后可通知群 |

> 只读操作（查看日志、看状态、导出数据）随便并行，没有任何影响。

## 6. 常用巡检命令（连接后直接用）

```bash
# 服务状态
systemctl is-active rm-progress frpc

# Web 自检（应返回 200）
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:80/login

# 温度 / 磁盘 / 内存
vcgencmd measure_temp
df -h /
free -h

# 最近日志
sudo journalctl -u rm-progress -n 30 --no-pager
sudo journalctl -u frpc -n 30 --no-pager

# 备份列表
ls -lh /opt/rm-progress/backups/

# 手动备份一次
/opt/rm-progress/deploy/backup.sh
```

## 7.（可选）校外远程维护 SSH

如果以后需要在实验室外 SSH 维护，可加一条 frp 映射 + 云服务器放行，步骤（需服务器管理员配合）：

1. 树莓派 `/opt/frp/frpc.toml` 追加：
   ```toml
   [[proxies]]
   name = "xtyf-progress-ssh"
   type = "tcp"
   localIP = "127.0.0.1"
   localPort = 22
   remotePort = 10022
   ```
   然后 `sudo systemctl restart frpc`
2. 云服务器安全组放行 TCP `10022`（建议只放行你常驻的固定 IP，不要 0.0.0.0/0）
3. 校外登录：`ssh -p 10022 -i 密钥 xtyf@47.116.50.22`

安全建议（做之前务必确认）：
- 树莓派的 SSH **只允许密钥登录**（当前即如此），并考虑 `fail2ban`
- 暴露 SSH 端口存在被扫描爆破风险，**非必要不开**；如开，务必限制来源 IP
