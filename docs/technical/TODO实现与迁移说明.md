## 迁移概览

`modules/task_migrations.py` 通过 `schema_migrations` 记录升级版本并用 SQLite 事务执行：

- v1：创建任务扩展关系（树、依赖、参与者、修订、截图等），从旧成员/任务字段迁移目录引用。
- v2：把历史中使用分号拼接的专业组拆分为多组关联，**仅一次**预置六个专业组。
- v3：新增 `member_projects`，**仅一次**根据历史任务的负责人/参与者与 `project_id` 推断成员参与的造车组别；默认预置步兵/哨兵/重装/飞镖，并保留旧细分项目。

`task_groups` 仍为历史数据/API 兼容存在，不再决定任务造车组别归属。`members.group_name` 与 `tasks.project` 等旧字段不是新关联的权威来源。

成员、专业组、造车组别的 `deleted_at` 表示软删除，管理员可恢复；**任务逻辑删除目前没有恢复入口**。

## 本轮安全与发票归属迁移

主应用初始化新增 `security_migrations`，与任务的 `schema_migrations` 分开计数：

- v1：添加 `members.must_change_password`、`member_permissions` 和 `security_audit`。现有账号默认不强制改密；新建、导入、重置与初始管理员必须改密。旧 `FUNDS_REVIEWERS` 仅在此时绑定已有成员 ID；当时有效的管理员/项管保留发票管理权限。
- v2：一次性处理发票元数据：姓名在所有成员（含停用/删除）中唯一时绑定 ID；同名、缺失、无效归属保留待确认。之后不再退回姓名授权，也不因新建同名成员重新认领。管理员先在“权限与审计”授权财务，财务在发票页筛选“归属待确认”，选择明确的成员 ID。

财务权限配置和请求审计入口为 `/admin/security`。发票后台任务另外记录开始/结果，进程中断的记录保留“未完成”。审计不记录密码，不等于跨数据库事务或可恢复任务队列。发票 JSON 使用单进程锁和原子替换，依旧要求单 worker。

浏览器页面自动提交 CSRF；非浏览器客户端必须先取得 Cookie 和 `/api/csrf` 令牌，登录后更新响应头令牌。旧测试夹具也需接入首次改密和显式财务授权；本轮按要求未运行功能测试，迁移及浏览器验收仍待后续会话。
