# 任务紧急度综合评分（PR #29）

任务中心「按人」视图在每个成员名下对该成员关联的未完成造车任务计算综合紧急度（0～100 分），默认仅显示最紧急的一项；其他未完成任务可展开。已完成、已取消任务不参与活跃任务排序，默认折叠；明确筛选这两种状态时仍可直接看到结果。

## 评分权重

| 维度 | 评分 |
| --- | --- |
| 职责 | 总负责 +28；参与者 +8；其他 +0。若既是总负责又在参与名单内，仅计 +28 |
| 截止紧迫度 | 0～44 分；逾期 6 天以后封顶，不会一直递增 |
| 任务优先级 | 高 +20；中 +10；低 +0 |
| 当前状态 | 阻塞 +8；进行中 +4；未开始 +0 |

截止紧迫度的日历天数（由服务端统一计算）：

| 距截止日期 | 分值 |
| --- | ---: |
| 已逾期 1 天 | 39 |
| 已逾期 2～5 天 | 40～43 |
| 已逾期 6 天及以上 | 44（封顶） |
| 今天 | 36 |
| 1 / 2 / 3 天后 | 32 / 28 / 24 |
| 4 / 5 / 6 / 7 天后 | 20 / 18 / 16 / 14 |
| 8～14 天后 | 12～6（逐日递减） |
| 15～30 天后 | 5～0（每三天递减 1） |
| 超过 30 天或无有效截止天数 | 0 |

已完成和已取消任务综合分为 0，且不论其他因素，始终排在未完成任务之后。分数相同时优先比较职责，再比较高/中/低优先级与当前状态，最后按任务 ID 升序稳定排序；**不使用超出封顶的逾期天数来破坏并列**。

## 具体例子（相对于同一个成员）

| 任务 | 职责 | 截止 | 优先级 | 状态 | 总分 |
| --- | --- | --- | --- | --- | ---: |
| 明天截止的紧急参与任务 | 参与 +8 | 明天 +32 | 高 +20 | 阻塞 +8 | **68** |
| 高优先级、没有截止时间的主责任务 | 总负责 +28 | 无期限 +0 | 高 +20 | 阻塞 +8 | **56** |
| 今天截止的低优先级主责任务 | 总负责 +28 | 今天 +36 | 低 +0 | 进行中 +4 | **68** |
| 逾期 7 天的高优先级主责任务 | 总负责 +28 | 已封顶 +44 | 高 +20 | 阻塞 +8 | **100** |
| 逾期 200 天的高优先级已完成任务 | 已完成 | 不计 | 不计 | 不计 | **0（折叠）** |

该方案兼顾职责与真正紧急的时间节点，不是评估实际工作量的模型。排序仅在浏览器展示时计算，不会改写存储的任务优先级、期限、状态或分配关系，也不需要数据库迁移。

## 主页工作台「近期任务」排序

首页展示全团队的未完成任务，默认按得分从高到低选取前 **8** 项，完成/取消任务不占名额。截止紧迫度、任务优先级及状态分与任务中心完全相同，但主页采用独立的职责权重：

| 与当前登录人的关系 | 主页职责加分 |
| --- | ---: |
| 我总负责 | 28 |
| 我参与（非总负责） | 8 |
| 与我无关的团队任务（含未分配） | **4** |

因此，同等日期、优先级、状态下，自己参与的任务只比不相关的团队任务多 **4** 分；但团队已逾期的高优先级任务仍可能超过一个自己的不紧急任务。排序不是先把「我的任务」整体置顶再接团队任务，而是全团队统一计算分数。得分相同时按职责、优先级、状态、任务 ID 决胜。

主页任务卡片标注「我总负责」「我参与」或「团队任务」，便于理解排序。**此 +4 权重仅适用于首页**，任务中心按人视图未改动，任务中心对不相关任务依旧加 0 分。



## 自动化验证

JavaScript 单测覆盖：主责/参与交叉优先级、负责人重复列入参与人防止双重计分、缺失和异常日期、逾期封顶与临界天数、不同优先级和状态、已完成/取消折叠、状态筛选、总分上下界、相同分数的稳定决胜、160 条混合任务的排序传递性。浏览器端额外使用混合数据验证默认第一张卡片、展开顺序与归档折叠交互。工作台近期任务通过显式传入团队任务 +4 的权重，复用任务中心的评分函数；另有工作台混合任务的 JavaScript 单测和真实浏览器 DOM 顺序测试。
