## 主题偏好

| 模式 | 标识 | 界面名称 |
| --- | --- | --- |
| 亮色 | `silver` | 银白蓝 |
| 亮色 | `rm-light` | RM 机甲红蓝 |
| 亮色 | `mist` | 云雾绿 |
| 亮色 | `paw` | 奶霜猫爪粉 |
| 暗色 | `space` | 深空蓝 |
| 暗色 | `rm-dark` | RM 机甲红蓝 |
| 暗色 | `graphite` | 石墨灰金 |
| 暗色 | `xueli` | 雪梨星语 |

成员可选择 `light`、`dark` 或 `system` 模式，同时分别保存亮色与暗色配色。系统模式由设备的 `prefers-color-scheme` 决定当前使用哪套配色；侧栏快捷切换会切换亮暗模式并退出系统模式。账户设置及顶栏外观菜单使用同一套账户偏好。

`GET /api/account/preferences` 返回：

```json
{"ok":true,"theme":"light","mode":"system","light_theme":"paw","dark_theme":"xueli"}
```

`POST /api/account/preferences` 接受完整的三个字段：

```json
{"mode":"system","light_theme":"paw","dark_theme":"xueli"}
```

该接口仅修改当前账户，不能指定其他成员。缺少字段、额外字段、跨模式配色或非法类型返回 `400`，合法字段不会先行保存。权限与 CSRF 校验沿用现有机制；更改外观不会递增会话版本或使其他设备退出登录。其他设备刷新后读取保存的偏好。

旧客户端仍可提交 `{"theme":"light"}` 或 `{"theme":"dark"}`；这会切换模式，但保留已选的两套配色。响应保留旧 `theme` 字段。系统模式下，`theme` 表示旧版客户端使用的亮暗回退值，不代表所有设备的实际系统模式；新版浏览器自行判断系统亮暗。

服务端模板输出账户偏好，页面首屏脚本在样式绘制前处理系统模式。完整页面仍通过 `data-theme` 保留两模式兼容，并通过 `data-palette` 使用具体配色。主题保存失败时恢复原主题，显示可读反馈并保留待重试的选择；用户可明确点击重试，不自动重复提交写请求。

## 全局目标倒计时

工作台顶部显示一个全体成员共享的目标。仅管理员看到“设置目标日期”按钮，普通成员和项管可以读取但不能修改。目标名称最多 80 字；日期采用严格的 `YYYY-MM-DD` 日历日期，不含时间或时区。

`GET /api/workspace/countdown` 返回：

```json
{
  "ok": true,
  "countdown": {
    "title": "完整形态考核",
    "target_date": "2026-11-01",
    "version": 1,
    "configured": true,
    "today": "2026-10-16",
    "days_left": 16
  }
}
```

管理员使用 `PUT /api/workspace/countdown` 提交完整对象：

```json
{"title":"完整形态考核","target_date":"2026-11-01","version":1}
```

成功后版本递增。请求必须携带最近读取的整数版本；旧版本返回 `409` 并附上当前 `countdown`。名称和日期同时清空可隐藏横幅；只清空其中一个返回 `400`。未配置时 `configured=false`、`days_left=null`，普通成员不显示空横幅，管理员仍可设置目标。

倒计时按北京时间的日历日期相减，避免浏览器时区、夏令时或当天具体时刻影响天数。未来显示剩余天数，当天显示“今天”，过期显示“日期已过”，不推断活动已经结束。前端每分钟及页面重新可见时更新显示，不重新请求或替换正在编辑的表单。

保存期间禁用重复操作。失败保留输入；版本冲突或网络中断导致结果未知时，须明确点击“加载最新设置（替换当前输入）”，核对后再保存。普通请求使用现有 15 秒超时，不自动重试写请求。请求审计记录操作者、接口、结果、日期与版本变更，不记录自由文本目标名称。

## 任务中心与开始日期

统一入口为 `/tasks`。造车任务使用默认页签，日常项目使用 `/tasks?type=daily`；日常项目详情链接为 `/tasks?type=daily&project=ID`。旧 `/daily-projects` 及详情地址重定向至新入口，登录后回跳和邮件链接兼容新地址。

这次只合并入口，不迁移日常项目到造车任务表。日常项目继续保留机械、电控、视觉分组、多人负责人、组别进度、附件、版本与原权限。原有造车任务依赖、进度记录及排期继续使用自身数据结构。

新建造车任务时，仅以**主前置任务**的截止日期减去两个日历日生成开始日期建议，其他前置任务不参与该默认值。首次保存后日期固定；更换前置任务、前置任务延期或轮询不会覆盖已保存日期。手动设定或清空日期也会明确记录来源，不通过数值是否恰好等于建议值猜测。

可编辑该任务的成员可以明确重置为当前依赖建议。`reset_start_date: true` 由服务端重新计算；主前置无有效截止日期或计算结果与截止日期冲突时，整次修改失败，其他字段不保存。`start_date_origin: "manual"` 可显式保存手动日期（包括空值）。来源字段为 `frozen`、`manual`、`dependency`、`schedule`；来源不表示持续联动。管理员／项管确认应用排期属于另一次明确操作，可以调整日期；修订与撤销同时保存或恢复日期来源。

## 数据迁移与交付边界

应用初始化依次执行任务迁移与工作台设置迁移：

- 任务迁移 v6 增加 `tasks.start_date_origin`，既有记录标记为 `frozen`，不重算任何任务日期。
- 任务迁移 v7 与日常项目幂等迁移增加 `completed_at`，供 22:00 团队晚报识别当天完成事项；仅真实完成状态转换记录北京时间，历史未知完成日期保持空值，修改标题或日期不重写完成时间。
- 工作台迁移增加 `members.theme_mode`、`light_theme`、`dark_theme`。保留原 `ui_theme` 的 `light/dark` 限制；首次升级把旧亮暗选择复制到模式，新配色默认 `silver/space`。
- 新增单例表 `workspace_countdown`，首次为空，后续升级不覆盖配置或版本。
- 迁移可重复执行，不移动、删除或重建既有日常项目、负责人关系、进度、附件或任务记录。

后续发布需同批更新后端、模板、脚本、样式及 `static/theme-assets`。发布前依现有运维流程备份数据库和附件；本次开发不自动推送、部署或开启真实邮件投递。原独立 stash 不恢复、不合入、不删除。
