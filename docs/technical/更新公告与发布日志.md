# 网站更新公告与 Git Commit 时间轴

- 发布前运行 `python deploy/package_release.py`；它从同一 `HEAD` 创建源码归档、签名 UI 和 `site-release.json`。元数据包含打包时间（UTC）、完整发布 Commit SHA、最近最多 200 条 Commit 的时间、作者、标题和 SHA。发布包的 manifest 校验并保护这份快照。
- 按既有流程上传归档，在服务器执行 `sudo python3 deploy/update_release.py`。部署工具切换运行目录后，Flask 从本地快照读取更新日志，**不调用 GitHub API，不读取服务器的 Git 历史**。
- 如使用旧的 `bash deploy/deploy.sh` 从 Git Checkout 直接同步，脚本在本机有 Git 时会生成相同快照；直接同步非 Git 目录而没有快照时，更新日志显示说明信息、公告保持隐藏，不会阻止业务服务启动。打包流程始终推荐优先使用。
- 登录成员在各页面顶部看到公告，右侧“查看详情”进入 `/updates`；侧栏“更新日志”入口始终保留。首次发现版本或服务器变更版本时会提醒一次，关闭/进入详情视为已读。已读标记存在此设备浏览器的 `localStorage`，按成员 ID 隔离；清除浏览器数据或切换设备会再次看到通知。
- 浏览器每 60 秒、重新聚焦标签页时请求 `/api/site-release`；接口仅对登录用户提供版本概要，禁用缓存，且不会暴露账户/数据库信息。时间轴 `/updates` 经 `/api/site-release/history` 读取同一份缓存，并通过 `textContent` 安全构造 DOM，在网页和已打包客户端中一致展示。所有接口仅对登录成员开放。
- 旧版本或未生成快照时 API 返回 `available: false`，不会弹出误报。时间轴按提交时间排序；**这是 Git 提交记录，不等同于人工撰写的版本变更说明**。如果一次部署跨越多个版本，页面仍提供全部已缓存的近期记录，未做上一次部署与本次部署的 SHA 范围筛选。
- `site-release.json` 是打包生成物，已经加入 `.gitignore`，不得手工提交。客户端安装包发布仍按 `clients/README.md` 的独立流程执行。

验证：`python -m unittest discover -s tests -p 'test_site_updates.py' -v`；`node --test tests/js/site_updates.test.cjs`。PR CI 会检查 Python、JS 和浏览器集成测试。
