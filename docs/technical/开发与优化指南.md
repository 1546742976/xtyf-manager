# 开发与维护指南

基准：2026-10-13 `main`。项目使用 Flask、SQLite、Jinja 模板、原生 JS/CSS；**不需要 Node 前端打包器**。

## 环境和启动

建议 Python 3.13（CI 使用），安装 Node.js 22 仅用于前端脚本语法检查。

    git clone https://github.com/SHM-white/xtyf-manager.git
    cd xtyf-manager
    python -m venv .venv
    # Linux/macOS: source .venv/bin/activate
    # Windows PowerShell: .venv\Scripts\Activate.ps1
    python -m pip install -r requirements.txt
    python app.py

默认访问 `http://127.0.0.1:8520`。生产部署不应使用本地开发服务器。首次空库创建 `admin`；建议在启动前使用 `PROGRESS_INITIAL_ADMIN_PASSWORD` 指定独立密码，否则日志会输出一次随机初始密码。

建议用**专用临时目录和临时数据库**测试，不要把真实服务器数据复制到公开工作目录或交给 CI：

    # Linux/macOS 示例
    PROGRESS_DB=/tmp/xtyf-test.db PROGRESS_SECRET_PATH=/tmp/xtyf-secret.key python app.py

`FUNDS_DIR`、`INVOICES_DIR`、`TASK_ATTACHMENTS_DIR` 也应指向隔离数据目录（详见[配置参考](配置与权限参考.md)）。不能仅改 `PROGRESS_DB` 就认定所有财务/附件数据隔离。

## 文件组织与扩展方式

- `app.py` 负责初始化与页面，任务逻辑主要在 `modules/task_*.py`，不要继续向 `app.py` 堆积任务规则。
- 成员资料在 `modules/member_profiles.py`，两类组别与成员关系在 `modules/task_catalogs.py`，迁移在 `modules/task_migrations.py`。
- 资金与发票分别由独立 Blueprint 管理；页面位于 `templates/`，JS/CSS 位于 `static/`，**不要再查找不存在的发票“Python 内嵌整页 HTML”**。
- 涉及成员身份、组别和任务关系时使用稳定数据库 ID；不要把用户名、真实姓名或专业组名称当作外键。
- 新增接口需要服务端鉴权、字段白名单和失败回滚；表单隐藏字段不替代后端权限检查。
- 新增任务字段要同步检查迁移幂等性、版本冲突、修订前后值、导出兼容和历史数据处理。

## 提交前检查

    python -m compileall -q app.py common.py modules tests
    python -m unittest discover -s tests -v
    # 在 Linux/macOS shell，安装 Node 后：
    for file in static/*.js; do node --check "$file"; done

Windows PowerShell 的 JavaScript 检查可以使用：

    Get-ChildItem static -Filter *.js | ForEach-Object { node --check $_.FullName }

CI 在 `pull_request` 和 `main` 推送上执行 Python 3.13 / Node 22 的同类验证。变更 UI 仍需要另行人工检查桌面与移动浏览器；CI 回归测试不是浏览器 E2E。

## 最小人工验收

1. 登录、退出、账户设置与旧会话失效。
2. 成员创建、批量导入、组别多选、资料编辑；管理员软删除与恢复后仍停用。
3. 任务新增、多人参与、两套组别过滤、树/依赖防环、冲突检测、修订撤销、截图权限及 CSV。
4. 资金审核资格限制、审核后修改重新待审、统计与 CSV。
5. 发票暂存确认、本人归属、重名历史数据、查重、状态切换、PDF 预览和 CSV/ZIP。
6. 在隔离环境进行数据迁移重入和联合备份/恢复验证。

## PR 与发布

- 从最新 `main` 创建功能分支，集中修改并一次性提交，减少重复触发 CI。
- PR 描述中区分“代码功能完成”“自动化测试通过”“真实浏览器/财务票据人工验收”“生产已部署”。
- 发布前先按照[发布检查与数据恢复](发布检查与数据恢复.md)执行生产一致性快照和回滚预案；**代码合并不自动代表服务已经部署**。
- 不在公开 PR、Actions 日志和文档中展示实际成员名单、数据库、私钥、发票 PDF 或账号密码。
