## 第一批：超级管理员

保留内部角色 `admin`，统一角色显示为超级管理员。由角色继承全部已定义管理权限，不写入独立授权表；新旧管理员均生效。`permission_is_current` 统一网站、客户端 bootstrap、发票 SSE 与后台认领的账号状态、首次改密、会话版本和权限校验。

权限列表增量返回 `explicit_permissions`、`inherited_permissions`，`permissions` 返回有效权限。超级管理员的独立授权编辑返回 409，页面显示“角色自带、不可单独撤销”。降级后不再享有继承权限，旧独立授权仍按原规则处理。权限提升不改变业务约束或仅本人编辑简介规则。

反例先运行：无独立授权的新管理员后台授权失败、旧角色名称两个失败已复现。修复后 Windows Python 3.11.8 专项 43 项运行、42 通过、1 个 POSIX 测试跳过；包含超级管理员、SSE、后台崩溃恢复、客户端权限、审计和安全稳定性。原 SSE 撤权测试改用独立授权项管，以保留真实撤权行为；管理员继承权限不能由删除授权表记录撤销，另由新回归覆盖。

复现：设置 `TMP`、`TEMP` 为工作区 `.venv/test-tmp`，`PYTHONPATH=tests`、`PYTHONUTF8=1` 后运行 `python -m unittest test_superadmin test_invoice_sse test_invoice_job_recovery test_client_api test_security_audit test_security_stability -v`。Ruff、前端语法检查通过。后续批次记录完整回归。

完整回归发现 4 项资金测试仍假定管理员没有审核权；改为使用无审核权的独立项管创建待审记录，保留无权审核、并发审核和删除保护检查。新增超级管理员入账自动审核断言，沿用资金模块既有规则。浏览器授权编辑失败场景也改为操作普通成员，仍验证失败恢复及重试。
