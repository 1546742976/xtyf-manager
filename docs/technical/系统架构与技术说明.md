# 巡天御风管理系统 · 系统架构与技术说明

面向对象：二次开发人员、运维人员
最后更新：2026-10-12

---

## 1. 系统总览

一套 **Flask + SQLite** 的轻量级战队管理平台，运行在实验室的树莓派上，通过 frp 隧道对外提供访问。包含三个功能模块，共用一个登录体系：

```
浏览器
  │
  ├─ 局域网 http://192.168.2.16
  └─ 校外 http://47.116.50.22:10030 / http://manager.skywalker-rm.online
        │  （云服务器 nginx → frps 10031 → frp隧道 7000）
        ▼
  树莓派 5 (Debian 13, arm64)
        │
   gunicorn --workers 1 --threads 8 --bind 0.0.0.0:80
        │
   Flask App (app.py + 2 个蓝图模块)
        │
   ├─ data.db            进度数据（成员/任务/日志）
   ├─ data/funds/        资金数据（funds.db + TXT 台账）
   └─ data/invoices/     发票数据（PDF 文件夹 + JSON 元数据）
```

## 2. 技术栈

| 层 | 技术 | 说明 |
|---|---|---|
| 后端 | Python 3.13 + Flask 3 | 单进程 gunicorn（1 worker / 8 线程）|
| 数据库 | SQLite（WAL 模式） | 三个库：进度、资金；发票用"文件系统 + JSON" |
| 前端 | 原生 HTML/CSS/JS（无构建） | 进度系统自研样式；资金页用 Bootstrap（CDN）；发票页内嵌 HTML |
| 图表 | matplotlib（Agg） | 资金统计图（服务端生成 PNG base64），已装 Noto CJK 中文字体 |
| PDF | pdfplumber | 发票金额/日期/发票号提取 |
| 隧道 | frp v0.71（frpc） | 树莓派 → 云服务器 47.116.50.22:7000，token 认证 |
| 进程 | systemd | `rm-progress.service`、`frpc.service`，开机自启+崩溃重启 |
| 备份 | cron + bash + sqlite3 | 每日 3:17 备份数据库，周日打包发票 |

## 4. 数据模型

### 4.1 进度库 `data.db`

```
members   账号：id, name, username, password_hash, group_name, role(admin/manager/member),
          is_active, created_at
tasks     任务：id, title, detail, owner_id, group_name, project, priority(高/中/低),
          status(未开始/进行中/已完成/阻塞/已取消), progress(已停用,固定0),
          start_date, due_date, created_by, created_at, updated_at
logs      任务更新历史：id, task_id, member_id, member_name, note, changes, created_at
```

> 剩余天数不入库，由 `/api/data` 接口按服务器北京时间实时计算字段 `days_left`。

### 4.2 资金库 `data/funds/funds.db`

```
records   id, record_type(进/出), amount, category, source_dest, applicant,
          invoice_count, handler, record_date, notes,
          review_status(待审核/已审核/空=历史视为已审核), reviewed_by, reviewed_at, created_at
```

每次增删改自动同步生成 `资金管理记录.txt`（utf-8-sig，含"审核"列）。

### 4.3 发票数据 `data/invoices/`

```
{月份}/{状态}/*.pdf         # 月份如 2026.10，状态：未报销/正在报销/已报销
.invoice_meta.json          # 元数据：状态/提交人/备注/类别覆盖/报销日期/标签/发票号
.invoice_cache.json         # 金额缓存（从 PDF 提取的金额）
.uploads/                   # 上传临时区（自动清理）
```

- 元数据键统一使用正斜杠相对路径（代码内做了 Windows `\` → `/` 归一化，兼容迁移）
- 标准命名：`{类别}-{金额}元-{供应商}-{发票号}-{日期}-发票.pdf`

## 5. 权限模型

| 装饰器/守卫 | 位置 | 作用 |
|---|---|---|
| `_invoices_guard` | invoices.py before_request | 登录即可进入发票模块 |
| `finance_required` | invoices.py | 发票管理类 API 仅 admin/manager（导出/整理/查重/批量等）|
| `_funds_guard` | funds.py before_request | 资金模块整体仅 admin/manager |
| `login_required` / `manager_required` | common.py | 进度系统通用权限 |

数据级权限（发票）：
- 成员：`/api/invoices`、`/api/stats`、`/api/submitters` 均在服务端按 `submitter == 当前用户名` 过滤；`/invoices/file/<path>` 与 `/api/open_file` 校验归属
- 上传入库时服务端强制 `submitter = 当前登录人`、`status = 未报销`（不可伪造）

## 6. 主要 API 一览

### 进度（app.py）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/data` | 看板全量数据（members/tasks + days_left）|
| POST | `/api/task` | 新建任务（manager+）|
| POST | `/api/task/<id>` | 更新任务（本人改状态；manager+全字段）|
| POST | `/api/task/<id>/delete` | 删除任务（manager+）|
| GET | `/api/task/<id>/logs` | 更新历史 |
| POST | `/api/member` `/api/members/import` | 添加/批量导入成员（manager+）|
| POST | `/api/member/<id>/reset|toggle|role` | 重置密码/停用/改角色 |
| POST | `/api/password` | 修改本人密码 |
| GET | `/export.csv` | 任务导出 |

### 资金（/funds/api/...）

`records`(GET/POST)、`records/<id>`(PUT/DELETE)、`records/<id>/review`(POST 审核)、`pending_review`(GET 待审计数)、`stats`、`chart`、`export`

### 发票（/invoices/api/...）

`invoices`、`stats`、`submitters`、`invoice/update`、`invoice/batch`、`upload`、`upload/batch`、`upload/confirm`、`upload/confirm/batch`、`upload/cleanup`、`check-duplicate`、`scan-duplicates`、`organize`、`organize/preview`、`refresh`、`job/start`、`job/stream/<id>`（SSE 实时进度）、`open_file`、`open_folder`、`export`、`export_zip`；文件预览：`/invoices/file/<path>`

> 注意：发票后台任务（整理/刷新/查重删除）用进程内字典 `_jobs` + SSE 推送，因此 gunicorn 必须保持 **1 个 worker**，否则任务态不一致。

## 7. 前端说明

- 看板每 5 秒轮询 `/api/data`（数据指纹没变则不重绘，避免闪烁）
- 任务卡片剩余天数徽章颜色规则：>3 天蓝、≤3 天橙、逾期红、无截止灰
- 发票页整页 HTML 由 `modules/invoices.py` 的 `create_index_html()` 生成；页面通过注入 `window.IS_FINANCE / window.ME_NAME` 控制成员/管理视角（隐藏管理按钮、锁定提交人）
- 资金页申请人自动填当前登录人（服务端兜底）；审核角标仅对 `chy` 显示

## 8. 部署形态与关键配置

- systemd：`/etc/systemd/system/rm-progress.service`（含 `AmbientCapabilities=CAP_NET_BIND_SERVICE` 允许普通用户绑定 80 端口）
- frp：`/opt/frp/frpc.toml`（映射 `xtyf-progress-http`: 本地80→远程10031；`xtyf-progress-tcp`: 本地80→远程10030）
- 备份：cron `17 3 * * * /opt/rm-progress/deploy/backup.sh`
- 云服务器（由服务器管理员维护）：frps 7000 端口、安全组放行 10030/10031、nginx 将 `manager.skywalker-rm.online` 转发到 `127.0.0.1:10031`
