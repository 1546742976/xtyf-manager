# 巡天御风管理平台 · 功能审计与 UI / 逻辑重构设计

> 本文记录第二轮（已合并到 main）的功能审计和历史状态；第三轮身份安全及发票归属的最新实现见 [第三轮安全与可靠性修复](第三轮安全与可靠性修复.md)。部署维持 HTTP，不将 HTTPS 纳入后续重构计划。

> 版本：2026-10-12，第二轮重构，基于 `refactor/project-layout-ui-20261012`。本文区分**已经实现**、**本轮实现**和**规划中**，避免把拟议功能误写成已有功能。

## 1. 产品目标与约束

战队成员通过同一个入口完成任务协作、发票提交；管理人员安排成员与任务，财务人员处理资金台账、发票管理和审核。平台面向桌面与手机浏览器。

兼容性约束：
- Flask + SQLite 保留，运行入口仍为 `app:app`；原 `/api`、`/funds/api`、`/invoices/api` 接口除新增响应字段外不随意改名。
- 保留已有 `data.db`、`data/funds/funds.db`、`data/invoices/` 与 `secret.key`；本轮**不迁移线上数据库、不自动部署**。
- 发票任务现已存于主库并使用同机跨进程锁；Gunicorn 默认保持单 worker，多进程和重启恢复待验收。
- 财务审批默认由现有审核用户名 `chy` 执行，现支持环境变量 `FUNDS_REVIEWERS=chy,xxx` 显式配置（必须是管理员或项管），避免直接扩权给所有管理员。

## 3. 已确认缺陷与风险分级

### P0：直接影响数据、权限
- 过去资金审核仅在前端按 `chy` 显示按钮，后端所有 admin/manager 都能调用 `/funds/api/records/<id>/review`。**本轮：在后端独立校验审核人，其他角色 403**。
- 已审核记录可以修改金额但不重新审核，构成审核绕过。**本轮：内容实际发生变更时清空历史审核结果，状态回到待审核**。
- 资金列表曾直接把记录字段拼成 `innerHTML`。**本轮：对动态字符串做 HTML 转义**，后续应统一用 DOM API 或可信模板。
- 使用固定成员初始密码 `123456`。**本轮：新建/导入/重置改为随机生成，且支持显式强度底线**；新密码仅在操作响应中显示一次。

### P1：功能错误 / 体验故障
- 发票「导出 CSV」旧实现只将 CSV 写入服务器，不会下载到用户浏览器。**本轮：新增 `/invoices/api/export/download` 附件接口**，旧接口保留兼容。
- 发票表格中的月份链接实际上调用「打开服务器文件夹」占位功能。**本轮：改为纯标签，避免无效入口**。
- 发票列表发起多次搜索/筛选时，旧请求可能比新请求晚返回并覆盖最新结果。**本轮：请求序号防乱序，失败给出提示**。
- 发票列表部分字段未经 HTML 转义直接渲染。**本轮：补充多个字段转义**，后续移除字符串式 `onclick`。
- 资金操作的失败信息混杂英文、删除后未检查 HTTP 返回状态；资金与发票页面脚本嵌在 HTML 中。**本轮：拆文件并提升错误反馈**。
- 发票分页和金额筛选参数可能抛出异常；用户名脚本注入可能破坏标签。**本轮：后端校验并进行脚本文本转义**。

### P2：设计与长期维护
- 三个页面分别维护自己的头部、样式和组件，风格不统一。**本轮：新增 `static/ui.css` 全局设计规范及统一导航层级**。
- 成员管理和资金/发票模块都是大型页面，缺少自动化 UI 测试；部分功能还依赖第三方 CDN 的 Bootstrap。
- 发票归属使用姓名匹配，而非唯一成员 ID，成员同名或改名会影响访问控制。**规划中**，需要先设计数据迁移与历史映射。
- 资金与发票金额已统一为 Decimal 逐笔舍入与整数分计算，金额 API 改为两位字符串；历史迁移与金额一致性测试按要求留待后续会话。
- 发票后台任务已持久化，排队任务重启接续，查重/金额刷新最多尝试三次；整理/删除中断需人工核对，PDF 与 JSON 的跨文件原子性仍待完善。

## 4. UI 信息架构

统一为五个主工作区：
1. **任务总览**：突出进度、异常、负责人、状态；信息密度适中。
2. **任务与成员**（项管+）：任务创建和管理、成员清单和授权集中管理。
3. **资金管理**（项管+）：收支统计、流水、审批、趋势图。
4. **发票管理**（所有登录者）：个人上传与详情；管理层显示财务处理操作。
5. **账户设置**（所有登录者）：个人信息、统一密码修改，不再依赖只有看板才存在的改密弹窗。

### 设计语言
- 背景使用冷色低对比画布，白色卡片/面板，蓝色主操作和青绿色状态辅助色。
- 同一导航组件的视觉语义：当前页高亮、明确用户区与退出按钮，移动端横向导航而非整站宽度溢出。
- 24/16/12px 的标题、内容、帮助文本三级阅读层次；表格保留横向滚动；小屏统计卡两列。
- 使用 CSS 变量统一颜色、边框、阴影、尺寸；遵守 `prefers-reduced-motion`；键盘焦点可见。
- 写操作要有「加载 / 成功 / 失败」反馈；不可用的操作不应显示成可点击链接。
- 不让 CSS 文案伪装为真实状态（例如财务审核人员必须由后端授权）。

### 前端文件约定
```text
static/
  ui.css            全局设计规范（所有页面共享）
  style.css         看板/通用原有组件，逐步向 ui.css 迁移
  app.js            通用 API、看板及密码弹窗行为
  manage.js         任务与成员管理页
  account.js        独立账户设置页
  funds.css/js      资金页面专属样式与业务交互
  invoices.css/js   发票页面专属样式与业务交互
templates/
  base.html         登录、看板、任务管理页骨架
  board.html        任务看板
  manage.html       任务与成员
  funds.html        资金页（保留 Bootstrap 依赖）
  invoices.html     发票页（保留服务端角色注入标记）
  account.html      个人资料与密码管理
```
