# 服务器运维手册

适用：树莓派 / Debian + systemd 的现有部署方案。本文给出通用命令，**不公开维护人员私钥位置或内部固定 IP**。具体机器地址、云服务器与端口映射以运维环境的私有配置为准。

## 运行模型

- `deploy/deploy.sh`：在源码目录运行，默认使用 `/opt/rm-progress` 作为部署目标；可用 `APP_DIR`、`APP_USER` 覆盖。
- `deploy/rm-progress.service`：Gunicorn `--workers 1 --threads 8 --timeout 120 --bind 0.0.0.0:80`，工作目录是运行目录；服务命令加载 `deploy/gunicorn.conf.py`，在 worker 启动后自动接续持久化发票队列；默认仍保持单 worker，调整并发前须验收。
- `deploy/frpc.toml`：FRP 参考配置；使用前检查真实运行环境、令牌及代理映射。
- 生产传输仍为 HTTP；请在受信网络、VPN 或明确的访问限制下使用，不要把 FRP token 认证等同于业务 HTTP 加密。

## 部署

2026-10-14 修复增加资金审核版本迁移，须同批更新前后端并刷新旧页面。初始化脚本 `seed_data.py` 需已初始化的当前数据库和完成初始改密的有效管理员；新增成员写入两套关联，首次登录必须改密，已有账号不重置，已删除目录项拒绝导入。

历史数据只读检查：`python deploy/audit_review_data.py --app-dir /opt/rm-progress`。如使用自定义位置，指定 `--database` 和 `--invoice-dir`（未指定时采用 `PROGRESS_DB`、`INVOICES_DIR` 环境变量或默认路径）。输出 JSON 诊断清单，不导入应用、不迁移、不重写数据；异常归属、金额及报销状态依据备份或管理员确认处理。

从已审核的 Git 提交更新源码目录，先备份并测试，再于设备上运行：

    cd /path/to/checked-out/xtyf-manager
    bash deploy/deploy.sh

脚本会安装 Debian 依赖、`rsync --delete` 同步源码至运行目录、安装 Python 依赖、写入 systemd 服务并重启。脚本排除 `data.db`、`data.db-*`、`secret.key`、`data/`、`backups/` 等；**但不要假定排除清单能自动保护存放在其他自定义路径的数据或私有配置**，部署前应检查 diff 和运行目录。

脚本本机自检请求 `http://127.0.0.1:80/login`。该命令可能给出 HTTP 状态码但仍需要管理员登录和业务功能验收。`deploy.sh` **不会自动安装 cron 或配置 FRP**。

## 常用检查

    sudo systemctl status rm-progress --no-pager
    sudo journalctl -u rm-progress -n 100 --no-pager
    curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:80/login
    df -h
    # 配置了 frpc 服务时：
    sudo systemctl status frpc --no-pager
    sudo journalctl -u frpc -n 50 --no-pager

**登录失败/页面旧版本**：检查 `journalctl`、源码 commit、部署输出、浏览器缓存；不要先改生产库。**发票 SSE 状态异常**：确认只启动了一个 Gunicorn worker。**组别数据异常**：先检查迁移记录及备份，不要手工改表。

## 备份及恢复

    # 当前脚本：数据库热备份、周日发票归档；并非统一完整备份
    APP_DIR=/opt/rm-progress bash deploy/backup.sh
    ls -lh /opt/rm-progress/backups/

如果计划每天 03:17 执行，需要由运维另外配置 cron 并确认实际生效；本仓库不自动安装。**统一恢复必须按[发布检查与数据恢复](发布检查与数据恢复.md)处理**，不要只恢复 `data.db` 后删除 WAL/SHM 而忽略任务附件和财务文件。

## 操作规范

- 生产更新安排单一负责执行者，避免多人同时 rsync 与重启造成覆盖。
- 新维护者生成**独立 SSH 密钥**，仅分发公钥。避免复制或共享既有私钥。
- 发票、资金、成员与截图均是受控数据；运维日志、备份及环境文件不应提交 Git。
- 数据库迁移可能在 Flask 初始化时发生。需要回滚时先停止写入并参照完整恢复点核对，不要默认旧版可安全读取新 schema。
- 参阅[异地接管与并行控制](异地电脑接管与并行控制指南.md)与[配置与权限参考](配置与权限参考.md)。
