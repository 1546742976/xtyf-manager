# 本地协作

`/discussions` 是团队内部的话题讨论板。所有有效登录成员可以发起话题、回复、阅读和下载附件；管理员、项管也可以参与讨论。此模块不再读取 GitHub 配置、令牌或订阅源，不导入远程历史。Git 远程和 GitHub Actions 与此功能无关，继续保留。

## 使用与权限

- 话题标题最多 120 字，消息正文最多 5000 字；正文或附件至少有一项。正文按纯文本显示，Enter 换行，Ctrl/Command + Enter 发送，输入法组词时不触发快捷发送。
- 桌面左侧话题、右侧对话；手机先选话题，返回按钮回到列表。话题按最新回复排序，20 项一页；消息一次 50 条，可向前加载。
- 作者只能在发送后不足 120 秒撤回消息。管理员、项管可随时撤回任意消息。作者撤回整话题还要求首条消息不足 120 秒且尚无回复；管理员、项管不受此限制。
- 撤回后显示占位，不支持编辑和恢复。原正文与文件长期保留在服务器，普通站内接口不再返回这些内容，下载与缩略图接口也会拒绝访问。
- 每个成员的已读位置保存在服务端；自己的消息和撤回消息不计未读。打开页面不直接清空未读，消息进入阅读区域后才推进。当前话题每 5 秒检查新增和撤回，隐藏页面暂停；导航每 30 秒检查未读。阅读旧消息时使用“有新消息”入口继续阅读。
- 本模块没有私信、私密话题、语音、Markdown、@提醒或邮件通知。每天北京时间 22:00 的项目晚报保持原有规则。

## 附件及失败恢复

支持所有扩展名和无扩展名文件：单文件最多 100 MiB，每条最多 5 个，总计最多 180 MiB。原始文件字节不变，原名作为下载文件名。可安全解码且不超过 2000 万像素、边长 10000 的 JPEG/PNG/WebP/GIF 另生成静态缩略图；超限或解码失败仍作为普通文件保存。HTML、SVG、脚本、压缩包和可执行文件不内嵌执行、不解压。

普通请求超时 15 秒、上传 180 秒，发送期间禁止重复点击。超时或断网保留文字和已选文件，使用提交标识核对是否已经成功；手动重试复用原标识，避免重复消息。任一附件保存失败时整条消息不发布并清理该次暂存文件。切换话题保留本页草稿，刷新页面不保证保留文件选择。

## 数据与接口

新增独立协作表保存话题、消息、附件、已读位置和变更记录；启动时执行可重复增量迁移，不改写造车任务、日常项目或邮件表。提交标识按成员唯一，创建话题和发送回复共用去重空间。写入沿用登录、CSRF 和审计，审计不复制正文或文件内容。

| 接口 | 用途 |
| --- | --- |
| `GET/POST /discussions/api/topics` | 搜索分页 / 新建话题 |
| `GET/POST /discussions/api/topics/<id>/messages` | 最近 50 条、before 历史分页 / 回复 |
| `GET /discussions/api/topics/<id>/changes?after=<cursor>` | 新增与撤回增量 |
| `POST /discussions/api/messages/<id>/withdraw` | 撤回消息 |
| `POST /discussions/api/topics/<id>/withdraw` | 撤回话题 |
| `GET /discussions/api/submissions/<submission_id>` | 核对本人的提交结果 |
| `GET /discussions/api/unread` | 全站未读统计 |
| `POST /discussions/api/topics/<id>/read` | 单调推进已读位置 |
| `GET /discussions/api/attachments/<id>/download` | 登录且未撤回时下载原件 |
| `GET /discussions/api/attachments/<id>/thumbnail` | 同权限下读取安全缩略图 |

旧 `/discussions/api/items`、`/discussions/api/item/...` 返回 HTTP 410 停用提示，不连接 GitHub。新建/回复接受 JSON 或 multipart，字段为 `submission_id`、`body`（话题另需 `title`）；multipart 文件字段重复使用 `files`。

## 存储、备份和部署

附件存放 `TASK_ATTACHMENTS_DIR/collaboration`，随机存储名，禁止通过 static 或反向代理公开映射。原件下载采用流式响应，强制 `application/octet-stream`、附件 disposition 以及 `X-Content-Type-Options: nosniff`；访问时同时校验有效登录、话题和消息状态。

默认布局 `data/task_attachments/collaboration` 在完整快照 `deploy/consistent_snapshot.py` 的递归附件范围内；新表随主 SQLite 的一致备份保存，恢复时数据库与附件必须成套恢复。升级工具 `deploy/update_release.py` 保留该附件目录。**如自定义附件目录在默认数据布局之外，必须在备份前按现有完整快照要求映射/整理，不能假设工具自动跟随环境变量。**

`deploy/backup.sh` 的日常数据库及发票分时备份不含任务/协作附件，不能当作完整恢复点。已撤回原件长期保留，需将它们计入容量规划与完整备份；失败上传的临时文件不属于保留内容。本次不启用新的生产备份任务。

Flask 全局请求上限仍为 200 MiB；服务模板 Gunicorn 超时为 240 秒。若使用反向代理，须允许至少 200 MiB 请求（含 multipart 开销），读取/转发等待时间应覆盖 180 秒上传窗口，建议至少 240 秒；例如 Nginx `client_max_body_size 200m; client_body_timeout 240s; proxy_read_timeout 240s; proxy_send_timeout 240s;`。实际配置由部署者核对，修改仓库模板不会自动更新已运行服务。

## 验收边界

测试使用隔离数据库和文件夹，不连接 GitHub 或真实 SMTP。浏览器模拟设备不等同于苹果/安卓真机；生产服务、真实设备及 Staging UAT 的结果独立记录。当前验收结果见本目录对应验收记录。
