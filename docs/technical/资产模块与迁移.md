# 资产模块与迁移

## 结构及参考

模块复用 `common.get_db()`、`PROGRESS_DB`、现有成员 ID、登录、CSRF 和首次改密保护。无独立库存数据库、外部服务或新增 Python 运行依赖。

参考 [InvenTree](https://github.com/inventree/InvenTree) 的[库存位置及日志](https://docs.inventree.org/en/stable/stock/tracking/)，以及 [Snipe-IT](https://github.com/grokability/snipe-it) 的[借用品和耗材分类](https://snipe-it.readme.io/docs/overview)。[Part-DB](https://github.com/Part-DB/Part-DB-server) 也适合电子元件，但其 BOM/EDA 等范围不在本轮内。项目分别采用 Django/MIT、Laravel/AGPL-3.0、Symfony/AGPL-3.0-or-later；本模块独立实现，没有复制其代码或引入这些技术栈。

新增表：`asset_campuses`、`asset_items`、`asset_stock`、`asset_loans`、`asset_events`、`asset_requests`。库存按物品与校区唯一。流水禁止 UPDATE/DELETE；纠错以 `corrects_id` 唯一关联原记录。成员姓名使用快照，目录维护保存前后内容。未还借单独立保存，分批归还不改原借用数量。

所有写操作在 `BEGIN IMMEDIATE` 中校验、改变数量和追加流水，同事务保存请求结果。`request_id` 按操作者唯一，相同内容重试返回同一结果，不同内容复用返回 409。盘点使用分校区库存版本，目录编辑使用目录版本。库存不能为负；每笔数量及单校区在库上限为十亿。校区总览批量聚合，不逐物品新增数据库查询。

## 接口

页面为 `/assets`、`/assets?view=mine`、`/assets/detail?id=<ID>`。JSON 接口使用现有登录会话：

| 接口 | 用途 |
| --- | --- |
| `GET /api/assets/catalog` | 校区与当前管理能力 |
| `POST /api/assets/catalog/items`、`campuses` | 创建／带版本编辑目录 |
| `GET /api/assets/items` | 名称规格、类别、校区筛选，每页 20 条 |
| `GET /api/assets/items/<id>` | 物品及分校区库存、借出、累计领用 |
| `GET /api/assets/loans` | 未还借单，支持 `mine=1`、`item_id` 及分页 |
| `GET /api/assets/events` | 物品、校区筛选及分页流水 |
| `POST /api/assets/operations` | `receive/borrow/return/consume/adjust/transfer/correct` |

写接口携带 `request_id`。库存操作使用 `item_id/campus_id/quantity`；归还使用 `loan_id/quantity`；调拨增加 `target_campus_id`；盘点增加 `version`（无库存记录时为 0）；纠错使用 `event_id`。管理类操作必填 `reason`。请求中的成员身份不被采纳，以登录用户为准。

bootstrap 增量返回 `assets_enabled` 与 `permissions.manage_assets`，协议版本不变。原生桥和安装包版本不变；资产业务走既有认证请求通道。新增权限 `assets.manage` 由现有权限页面授予，管理员默认有管理权。

## 迁移与上线步骤

当前项目连接的是 SQLite，路径来自 `PROGRESS_DB`，未配置时为项目根目录 `data.db`。部署者应先确认正在运行的服务配置及实际路径，不创建另一份空库替代现有库。

1. 在部署窗口备份实际业务库，采用 SQLite backup API 或现有一致性备份流程，不能只复制 WAL 模式下的主文件；检查备份 `PRAGMA integrity_check` 为 `ok`。
2. 用备份的隔离副本验证新代码和重复迁移，确认原成员、任务、财务数据及数量保持不变。
3. 正式发布经授权后，停止旧服务写入并部署配套后端；`app.init_db()` 调用 `migrate_assets()`，只新增表、索引和保护触发器。原表数据不重置，资产目录初始为空。
4. 检查登录、权限和业务数据，再由管理员登记真实校区及期初库存。不要把测试库或合成数据复制上线。
5. 更新客户端签名页面资源仍遵循既有正式发布流程；保存源码不会自动更新线上客户端。

本轮没有执行上述生产部署步骤，也没有迁移本地真实业务库。测试使用临时 SQLite 数据库。

代码回滚保留新增表和流水。数据恢复不是代码回滚：如果要恢复旧快照，先列出快照之后的资产、成员、任务和财务差异并单独确认，不能直接覆盖。

## 验证入口

```text
python -m unittest discover -s tests -p test_assets.py -v
python -m compileall -q app.py common.py modules tests deploy
ruff check app.py common.py modules deploy tests
python -m coverage run --branch --source=app,common,modules,deploy -m unittest discover -s tests -v
python -m coverage report --fail-under=65
node --test tests/js/*.test.cjs clients/frontend/test_bridge.cjs
python clients/frontend/test_frontend.py
node tests/browser/assets.cjs
```

浏览器入口要求 Playwright 1.57.0，`REVIEW_PYTHON` 指向已安装项目依赖的解释器；脚本创建临时后端，测试网页及编译后本地界面。原生桥在浏览器中模拟，不代表 Windows WebView2、Android 真机或 Linux 原生运行验收。测试输出位于 Git 忽略的 `.build-tools/assets-check/`，CI 只上传根目录 PNG 与 `result.json`，不上传测试资源包、数据库或环境目录。
