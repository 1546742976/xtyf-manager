# 配置与权限参考

依据当前源码（`app.py`、`common.py`、`modules/funds.py`、`modules/invoices.py` 和任务模块）。下表说明应用读取的变量，不意味着现有部署脚本自动注入这些值。

## 运行时配置

| 环境变量 | 默认值 | 用途 / 注意 |
| --- | --- | --- |
| `PORT` | `8520` | 仅 `python app.py` 本地开发启动端口；Gunicorn 端口由 service 命令行固定 |
| `PROGRESS_DB` | 仓库目录下 `data.db` | 成员、任务、登录失败记录等主 SQLite 库 |
| `PROGRESS_SECRET_PATH` | 仓库目录下 `secret.key` | Flask Cookie 签名密钥；保持稳定，不进入 Git |
| `PROGRESS_INITIAL_ADMIN_PASSWORD` | 未设置时随机生成并写受限文件 | **只在首次空库创建 admin 时生效**；首次登录必须改密 |
| `PROGRESS_INITIAL_CREDENTIALS_PATH` | `initial-admin-password.txt` | 随机初始管理员凭据；独占创建，POSIX 0600 / Windows 当前用户 ACL；改密后删除，不纳入版本库 |
| `FUNDS_DIR` | `data/funds` | `funds.db` 和文本台账 |
| `FUNDS_REVIEWERS` | `chy` | 仅首次安全迁移读取旧用户名配置并绑定已有成员 ID；之后通过“权限与审计”管理，修改此变量不再改变授权 |
| `INVOICES_DIR` | `data/invoices` | PDF、缓存、元数据、临时上传和 `.invoice.lock`；同机所有进程必须共用同一目录 |
| `TASK_ATTACHMENTS_DIR` | `data/task_attachments` | 私有任务截图目录 |
| `GITHUB_REPOSITORY` | `SHM-white/xtyf-manager` | `owner/repository` 外链；配置为空或无效时不生成链接 |

示例（**仅开发环境**，请使用本机隔离目录）：

    export PROGRESS_DB=/tmp/xtyf-dev/data.db
    export PROGRESS_SECRET_PATH=/tmp/xtyf-dev/secret.key
    export FUNDS_DIR=/tmp/xtyf-dev/funds
    export INVOICES_DIR=/tmp/xtyf-dev/invoices
    export TASK_ATTACHMENTS_DIR=/tmp/xtyf-dev/task-attachments
    python app.py

首次运行前须确保数据库父目录已创建。生产可通过 systemd 环境配置这些变量，实际值由部署者管理，不应提交 `.env`、密钥和私有数据。

## 权限矩阵（服务端规则）

| 功能 | 成员 member | 项管 manager | 管理员 admin |
| --- | --- | --- | --- |
| 任务浏览 / CSV | 可 | 可 | 可 |
| 编辑自己负责或参与的任务一般字段 | 可 | 可 | 可 |
| 新建、管理与逻辑删除任务 | 不可 | 可 | 可 |
| 维护任务父子层级、撤销修订 | 不可 | 不可 | 可 |
| 修改自己的登录名/两种组别/密码 | 可 | 可 | 可 |
| 成员新建、导入、管理普通成员快捷操作 | 不可 | 可 | 可 |
| 修改完整成员资料、角色、真实姓名 | 不可 | 不可 | 可 |
| 成员或字典软删除/恢复 | 不可 | 不可 | 可 |
| 新增/重命名组别字典 | 不可 | 可 | 可 |
| 资金记录管理 | 不可 | 可 | 可 |
| 全部发票管理 | 需 `invoices.manage` 授权 | 需授权 | 需授权 |
| 配置财务权限 / 查看审计 | 不可 | 不可 | 可 |
| 审核资金 | 不可 | 仅配置审核人 | 仅配置审核人 |
| 上传、查看自己的发票 | 可 | 可 | 可 |

**特殊规则**：管理员不能修改自己的系统角色、停用/删除自己，不能通过管理接口重置自己的密码；本人改密需要验证原密码。成员 ID 永不允许直接编辑。专业组/造车组别都是业务关联，**不是权限角色**。

## 审核与发票接口（2026-10-14）

- 资金记录返回整数 `version`；实际编辑、审核成功递增，等值编辑保持不变。`POST /funds/api/records/<id>/review` 必须携带 JSON `{"version": 当前读取版本}`，并保留原 CSRF 和权限要求。缺失/非法版本 400，过期版本 409，不存在 404；客户端刷新后重新确认，不自动重试。
- 独立 `funds_revision_migrations` v1 通过 ALTER TABLE 增加 `version INTEGER NOT NULL DEFAULT 1`，不重建金额表，不改变既有 ID、金额或审核状态。
- 发票单张/批量确认与修改共用字段校验：文字字段必须为字符串，标签为字符串数组，日期为有效 `YYYY-MM-DD` 或空字符串，月份为有效 `YYYY.M` 或“未归类”，状态为既有枚举。
- 发票确认新增可选 `confirmed_date`、`confirmed_vendor`，显示、搜索及导出优先读取；缺失时使用历史解析，明确空字符串保持未知。金额仍优先使用 `confirmed_amount_cents`。
- [只读历史诊断与修复记录](全项目审查修复.md)说明孤立元数据、非法字段和旧脚本关联缺失的检查方式；工具不自动修复历史业务数据。

## 会话、文件与遗留风险

- 更改用户名、角色、密码或账户启停时会增加 `session_version`；普通自助改用户名/密码保留当前会话但撤销其他设备的登录。
- 登录失败限制按 IP+用户名计数：15 分钟窗口 6 次失败将锁定约 15 分钟；未信任未经验证的 `X-Forwarded-For`。
- 附件和发票文件必须通过后端资源权限校验，不可直接移动至公开 `static/`。
- 所有非 GET/HEAD/OPTIONS 请求校验会话 CSRF 令牌，包括登录、退出和上传。页面自动携带；脚本客户端先 `GET /api/csrf` 并保留 Cookie，随后提交 `X-CSRF-Token`；登录后按响应头更新令牌。`/logout`、发票 `/api/refresh` 与旧 `/api/export` 写入入口仅支持 POST。HTTP 流量仍未加密，部署方需限制可信网络/访问范围。
- 新建/导入/重置账号必须先改密，只放行账户设置、改密、退出及 CSRF 获取入口；普通升级不强制旧账号集体改密。
- `security_migrations` v1 一次性迁移旧审核人，并为当时有效的管理员/项管保留发票管理权限。新建账号及后续角色提升需管理员明确授权；授权实时读取，停用账号不可使用。
- v2 一次性按历史姓名唯一匹配 `submitter_id`，重名、缺失及无效 ID 保留为待确认；列表、统计、文件访问不再按姓名授权。在发票页勾选“归属待确认”，打开详情选择带 ID 的成员并保存。
- `security_audit` 保存业务写请求、财务导出及后台任务结果；“未完成”可能表示进程中断，审计不是跨库事务或防篡改存储。资金/发票已统一采用 Decimal 逐笔四舍五入、整数分计算；金额 API 返回两位字符串，另含 `*_cents` 整数字符串，迁移和一致性验收尚待执行。发票任务保存至 `invoice_jobs`，入队/结束与审计同事务提交；发票读改写锁支持同机多进程，不支持多个主机或网络文件系统。
