# 成员资料与登录账号编辑

## 身份字段

- `members.id` 为 SQLite 自增主键；登录会话中的 `uid`、任务 `owner_id` 和各关系表均通过此字段引用成员。**任何编辑都不允许修改 ID。**
- `members.username` 为唯一的登录名，与 `id` 不同；改名后只能使用新用户名登录。
- `members.name` 为真实姓名，由管理员统一维护；更名不会创建新用户，也不会改变任务归属。
- `role` 为系统权限（admin/manager/member），与专业组、造车组别两套关联独立。

## 界面和权限

| 功能 | 普通成员 / 项管本人 | 管理员 |
| --- | --- | --- |
| 修改本人登录用户名 | 可，账户设置 | 可，也可在成员管理统一编辑 |
| 修改真实姓名 | 不可 | 可编辑任意成员，包括本人 |
| 调整专业组和造车组别 | 可修改本人，多选 | 可编辑任意成员；保留项管原有代管入口 |
| 修改系统权限角色 | 不可 | 可编辑他人；不能修改自己的角色 |
| 启用 / 停用账户 | 不可 | 可编辑他人；不能停用自己 |
| 更新本人密码 | 必须填写原密码 | 本人同样必须验证原密码 |
| 重置他人密码 | 项管可重置普通成员 | 可重置所有其他成员，可指定密码 |

管理员在“成员管理”列表点击 **编辑资料**，可在单一表单一次完成姓名、用户名、专业组、造车组别、角色、启停状态及可选密码重置。项管仍可用现有快捷操作编辑成员组别、重置普通成员密码、启停普通成员。

所有已登录用户都可在 **账户设置** 修改个人用户名及所属专业组、造车组别；密码在另一个表单修改。姓名和系统角色只读。

## API

- `GET/POST /api/account/preferences`：读取或保存当前账号的主题，POST 只接受 `{"theme":"light"}` 或 `{"theme":"dark"}`，返回 `ok` 与 `theme`。登录与 CSRF 校验沿用现有规则，初始密码必须先修改。独立于资料表单，不接受其他成员 ID；修改主题不会增加 `session_version`。
- `GET /api/account/profile`：查看当前账号的公开资料（不返回密码哈希）
- `POST /api/account/profile`：本人修改 `username`、`group_ids`、`project_ids`，只允许这些白名单字段
- `POST /api/member/<id>/profile`：仅管理员编辑指定成员，支持 `name`、`username`、`group_ids`、`project_ids`、`role`、`is_active`、`new_password`（留空不修改密码）
- `POST /api/password`：本人验证旧密码后更新密码，保持原接口
- 原有组别编辑、角色切换、重置他人密码和停用接口仍可使用；本人不能通过“管理员重置”接口跳过旧密码验证。

`group_ids` / `project_ids` 接受 ID 数组，`is_active` 接受 JSON 布尔值。均为局部更新，不传字段表示保持不变。非法字段、ID、权限、角色或长度直接报错；重复用户名返回 HTTP 409。多字段更新及关联编辑在同一 SQLite 事务中执行，失败即回滚。

修改用户名、角色、启停状态或重置密码会增加 `session_version`，使其他已登录会话失效。自己修改用户名时自动更新当前会话版本，因此无须重新登录当前页面。数据读取始终以数字 ID 为准。

## 删除与恢复（可逆）

「成员管理」里管理员可删除成员、专业组和造车组别；所有删除均为 **软删除（归档）**，不物理删除主键，也不清理历史记录或关系表。

- **成员删除**：管理员输入目标登录用户名确认。账号设为停用、写入 `members.deleted_at` 并使已有会话失效。默认成员列表不再展示，管理员可勾选「显示已删除成员」后点击「恢复账号」。恢复后账号仍处停用状态，需要管理员明确「启用」，不会自动恢复登录。
- **专业组删除**：管理员输入组名确认，写入 `groups.deleted_at`；不再允许新成员分配，但原有关联和老任务修订引用保持不变。专业组字典保留带「已删除」标志的记录，可恢复。
- **造车组别删除**：管理员输入组名确认，写入 `projects.deleted_at`；不可用于新增任务或新成员关联，历史任务的 `project_id` 不变、组别名称仍可查看。造车组别字典支持恢复。
- **不可越权**：仅管理员能删除/恢复，且管理员不能删除自己的账号；非管理员的 API 直接拒绝，不能借浏览器手动提交绕过确认。
- **已删除组别**：创建/新分配时禁止使用，历史已有成员仍可保留或主动取消原关联。用户编辑资料时不会因旧的组别已删除就强制丢失原有关系。
- **幂等和兼容**：新增字段通过自动迁移添加；再次启动不应重新建立归档项或恢复删除状态。组别名 UNIQUE 约束保留，因此同名历史组别应优先恢复而不是重新创建。

新增接口：
- `POST /api/member/<id>/delete`，请求 `{"confirm_username":"目标用户名"}`
- `POST /api/member/<id>/restore`
- `POST /api/groups/<id>/delete`、`POST /api/projects/<id>/delete`，请求 `{"confirm_name":"完整组别名称"}`
- `POST /api/groups/<id>/restore`、`POST /api/projects/<id>/restore`

上线前仍应备份 `data.db`、WAL/SHM 以及关联附件目录。不可将归档当成 GDPR 等场景下的不可恢复物理清除。
