### 1.3 修改代码

| 文件 | 修改场景 |
|---|---|
| `app.py` | 进度系统路由/任务逻辑 |
| `common.py` | 登录态/权限/公共数据库访问 |
| `modules/funds.py` | 资金功能 |
| `modules/invoices.py` | 发票功能（含整页前端 HTML，搜索 `create_index_html`）|
| `templates/*.html` | 页面（Jinja，改动后需重启本地服务，浏览器 Ctrl+F5）|
| `static/app.js` `style.css` | 看板前端（改完直接刷新浏览器即可）|

开发原则：
- 中文界面；不引入前端构建工具（保持零依赖，直接用原生 HTML/JS）
- 新功能尽量做成独立 Blueprint，注册到 `app.py`（参考 funds.py）
- 涉及数据库字段变更：在初始化函数里用 `PRAGMA table_info` + `ALTER TABLE` 做迁移（参考 `modules/funds.py: init_funds_db`）
- 权限：页面/API 都要在**服务端**校验角色，前端隐藏按钮只是体验优化

## 2. 测试方法

## 3. 部署到树莓派

```powershell
# 1) 上传改动的文件到"源目录"
scp -i "$env:USERPROFILE\.ssh\rm_progress" "D:\Robotmaster\管理\progress_system\app.py" xtyf@192.168.2.16:/home/xtyf/progress_system/app.py
#    （多个文件同理；modules/、templates/、static/ 按实际改动传）

# 2) 执行部署（同步到 /opt + 安装依赖 + 重启服务）
ssh -i "$env:USERPROFILE\.ssh\rm_progress" xtyf@192.168.2.16 "cd ~/progress_system && bash deploy/deploy.sh"
```

要点：
- `deploy.sh` 同步时**保留**线上数据（data/、*.db、secret.key、backups），不会覆盖
- Python 代码变更必须走 deploy.sh（重启服务才生效）；static 下 JS/CSS 可直接 scp 到 `/opt/rm-progress/static/` 立即生效
- 模板（templates/）改动需要重启（Jinja 生产模式不自动重载）→ 走 deploy.sh
- 服务重启约 3 秒，队员无感知

回滚：重新传旧版文件 → 再次 deploy.sh。

## 4. 代码约定与已知限制

| 项 | 说明 |
|---|---|
| 无前端框架 | 所有页面是服务端渲染 + 原生 JS；发票页是内嵌大字符串（改的时候注意别破坏 JS 语法）|
| 单 worker | gunicorn 1 worker，发票后台任务(SSE)依赖进程内状态；**不要**改成多 worker |
| SQLite | 并发写极少（内部工具），WAL 模式够用；不要搬 MySQL 折腾 |
| 时间 | 服务器时区为北京时间（Asia/Shanghai）；剩余天数由服务端计算 |
| 明文 HTTP | 校外访问未做 HTTPS（已知项，见优化路线）|
| 发票页宽度 | 桌面版最小宽度 1024px，手机上体验一般（优化项）|

## 5. 优化路线（建议按优先级）

### P0（安全/基础）
1. **HTTPS**：域名已就绪，在云服务器 nginx 上给 `manager.skywalker-rm.online` 配 Let's Encrypt 证书（certbot），frpc 不用改；顺带把校内访问也跳 https
2. **登录防爆破**：登录接口加失败计数（如 5 次/分钟 IP 限流），或加图形验证码
3. **操作审计**：资金/发票的关键操作（删除、改状态、审核）落一条 audit 日志表

### P1（体验/效率）
4. **通知推送**：接入企业微信/飞书群机器人 webhook：
   - 资金待审（当前是站内角标，推送到群更及时）
   - 任务逾期提醒（每天早上扫一遍逾期任务推给负责人）
   - 发票状态变化（成员上传后通知财务）
5. **移动端适配**：发票页做响应式（卡片布局），看板列宽自适应优化
6. **任务日历/甘特视图**：`/calendar` 页，按截止日期可视化排期

### P2（功能增强）
7. **发票 OCR 增强**：pdfplumber 对部分版式识别不稳，可加规则库或调用发票查验接口（真伪校验）
8. **预算管理**：资金模块加"预算 vs 实际"对比（按项目/月份）
9. **数据大屏**：例会用的全屏看板（任务 + 资金 + 发票概览轮播）
10. **异地备份**：rclone 每晚把 backups/ 同步到网盘/另一台机器，防树莓派损坏

### 实施提示
- 每个优化独立开分支/目录，本地验证后 deploy；改动前先备份数据库
- 涉及权限或财务逻辑的改动，先和管理员（chy）确认规则
